# Дневник: отложенное прикрепление и относительное местоимение

Проверка на исходном дневнике, 12 октября 2026. База: `50baeeedc77ec1b745e82742259dcbf223acd58d`.
Исходный документ SHA256: `e1f39d7f418121ce5956be9410f058a14ef76f82c88a113df42570f5511d8e71`.
Точные входы, запросы, ответы, хеши runtime, результаты записи, replay и отзыва сохранены в [evidence](evidence/diary_relative_and_deferred_host.json).

## Изменения

Неразрешённое прикрепление предложной группы теперь откладывается: другие связи могут уточнить дерево, после чего вопрос возвращается с уже собранным поддеревом. Повтор без изменения дерева использует прежнее решение. Проход без прогресса заканчивается явным отказом. Устаревший вопрос удаляется только из списка текущих предложений уточнения; его Decision и альтернативы остаются в трассе.

Относительное местоимение, объявленное в грамматическом ресурсе, связывает слот придаточного с существующим актантом. Короткая закрытая проба выбирает целостное морфологическое чтение и роль местоимения. Падеж роли берётся у местоимения, а не у существительного в главном предложении. Для известного предиката роль дополнительно проверяется по валентности. Отдельная сущность для местоимения не создаётся.

Механизмы описаны в [дереве именных групп](COMPONENT_NOMINAL_TREE.md) и [уточнении областей](COMPONENT_REFINEMENT.md). Новый код местоименной проекции вынесен в отдельный небольшой модуль. Правил под имена или конкретные фразы дневника не добавлено; в TEST_ONLY-ресурс добавлен грамматический маркер «который».

В записи за 27 июля по-прежнему коммитятся **два фрагмента** — первая фраза и завтрак. Новый механизм улучшил структуру оставшихся областей, но не увеличил число её коммитов. Принятое ранее минимальное прочтение группы участниц остаётся явно помеченным предположением, а не доказанным разрешением.

## Что проверено фактическим исполнением

Для фразы о бумагах: общий entity Ref в двух ролях; проверенная валентность ARRIVE; отсутствие отдельного M местоимения; S-доступность описания без F-видимости; отсутствие выдуманной календарной даты/TimeAssertion. Отношение AFTER к чаю сохраняется.

Повтор исходных запусков не добавил вызовов исполнителя проб, тиков Ignition или записей ledger. Проверена загрузка новым экземпляром store. На отдельных копиях журнала проверены отзыв NOMINAL-link, binding бумаг и всего наблюдения: зависимые пути теряют доступность, независимые сохраняются; повторная загрузка даёт то же состояние.

Короткие пробы выполнял независимый агент по предъявленным вариантам; финальные прогоны использовали точное воспроизведение записанных запросов и ответов. Это не проверка качества локальной модели. Ресурсы TEST_ONLY; production-релиз, G0/G5 и полнота дневника не объявляются. Новые тестовые наборы не создавались, suite не запускался.

## Следующие препятствия

1. Именное управление внутри должности: «главнокомандующим Северным фронтом». Нужен общий структурный механизм, без списка должностей дневника.
2. Несколько обстоятельств одного события: конструктор должен предлагать соответствующую структуру, а не только перестановки цепочки вложения.
3. Контекстное морфологическое чтение OOV-имени «Аликс» в «провел вечер с Аликс»: доступные варианты пока не дают принятой структуры.
4. Выбор хозяина всей группы «в лес за архиерейской церковью» остаётся настоящим открытым вопросом после успешного построения её внутренней связи.
