# Дневник: две временные границы

База: `990d388bbbde91d8d873404df508bba22d0d6753`.
Контракт: [COMPONENT_CLOCK_RANGE.md](COMPONENT_CLOCK_RANGE.md).
Машиночитаемые свидетельства: [diary_clock_range.json](evidence/diary_clock_range.json).

| Недочёт | Как было исполнено | Как исполнено теперь | Причина |
|---|---|---|---|
| Составной интервал не представлялся | Отдельные clock и относительные событийные правила не замыкали две границы | Ресурсный CLOCK_RANGE + FIXED/WORD_CLOCK endpoints, варианты часов и конечного дня | Границы должны сохраниться даже при неизвестной дате |
| Сплошной regex-диапазон поглощал бы событие | Обычный temporal match исключал все попавшие токены из аргументов | Временными считаются только две boundary-группы, предикат между ними остаётся в композиции | Нельзя потерять «пошел дождь» при выделении времени |
| `до` требовал дополнительный BEFORE внутри clock-границы | COMPONENT_SCOPE_UNRESOLVED ещё до построения кандидатов | Проверка конкретного marker span и kind TEMPORAL_NOMINAL | Занятый грамматический маркер не создаёт второй независимый оператор |
| Неоднозначные границы могли бы стать вымышленной датой | Готового контракта записи не было | Символическое TimeAssertion + неизменяемый payload и строгая валидация | Датировка с неизвестной областью не эквивалентна недатированной опоре |

## Фактический прогон

Полный исходный файл не изменён, SHA256
`e1f39d7f418121ce5956be9410f058a14ef76f82c88a113df42570f5511d8e71`.
Использован прежний абзац [99117,99395), не переписанная удобная версия.
TEST_ONLY resource SHA256:
`b1dd6705749182f4da12d9fb0f034f20788aeac2295c023303f8e238c2ec06b4`.

**До: RESOLUTION_ONLY, ноль коммитнутых фрагментов. После: частичный APPLIED,
один фрагмент из исходного абзаца.** Это «С полудня пошел дождь до три часа
тридцать минут». Кандидат сохраняет дождь как SUBJECT, предикат остаётся
OPEN_LEXICAL; каноническая семантика погодного события не приписана автоматически.

TimeAssertion содержит обе исходные границы, неизвестные lo/hi и три
реализации: 12:00 → 03:30 следующего дня, 12:00 → 15:30 того же дня,
12:00 → 15:30 следующего дня. Отсечение до единственного дня не делалось;
свидетельство не означает CONTINUOUS и не даёт произвольный датированный YES.

Итоговый прогон: четыре короткие пробы. Первая исполнена новым изолированным
агентом (`1`); три последующие (`1`, `1,2`, `1`) воспроизведены транспортом
из свежего диагностического запуска этого же прохода только после **точного
сравнения полного request JSON**. Исходные три ответа также получены
изолированными исполнителями без кода/gold/истории. Transport receipts и хеши
сохранены в evidence. Это не тест локальной модели и не измерение её скорости.

Неоднозначность «Завтракали и обедали на балконе» сохранена, отдельные
конъюнкты не выброшены в AH. Именные группы и приложения остальных предложений
не объявлены разобранными. Полной формализации ни абзаца, ни дневника пока нет.

Канонический повтор: 4 → 4 вызова, 50 → 50 тиков Ignition, тот же batch_hash и
состав фрагментов. Ledger до/после:
`d2c1df052e8ba5496f0a4b5d2c2e90983b08a9052d65b3b20917f1a7bbde95f5`.

## Проверки

178 проверок связанного набора прошли за 7,22 с. Затем добавлена проверка
точного marker span: финальный набор интервалов 17/17 за 0,53 с (16 пересекаются
с общим набором), всего **179 различных целевых проверок**.
Проверены T5/T6, journal-backed replay, восстановление свежего AH из журнала,
отзыв, неизвестный/явный якорь, порядок границ, некорректные числа, конфликтующие
правила, отсутствие языкового словаря в runtime, сохранение промежуточного
предиката и неприменимость подавления к другому вхождению scope-маркера.
Полный прежний suite не запускался. Готовность production и статусы ворот не
повышены.

Полный дневник дополнительно прошёл генераторную инвентаризацию без модели и
T6: 17994 токена, 4251 рамка, 521 запрос в 234 окнах, 42,93 с. До изменения:
4246 рамок, 520 запросов; COMPONENT_SCOPE_UNRESOLVED уменьшился со 144 до 143.
Это диагностические счётчики кандидатов, не число понятых предложений.

Остаются: рекурсивные NP/PP-деревья и генитивные связи, приложение «министр
юстиции», полное перечисление межклаузных областей модификаторов и их
ресурсная семантика. Повторные ответы модели сами эти структуры не создают.
