# Качественное количество и символическая временная граница

Нормативное дополнение V7 §3/§4.7/§6.3/§17. Слова источника сохраняются с
исходной точностью. «Несколько», «много», «мало» не получают вычисленных
кардинальностей, порогов или списков вымышленных участников. «До трёх часов»
не превращается в точное время события. Сборка типизированного графа выполняется
кодом; модель отвечает только на закрытые вопросы о предложенных связях.

## Количественная именная группа

Ресурсный opt-in: `ProposalPolicy.composition.qualitative_quantity` с
`version=LEXICAL_GROUP_V1` и `rules[{rule_id,lemma,POS=NUMR}]`.
Текущий конструктор рассматривает соседние NUMR + NOUN(gen, plur). Наличие
ADVB-анализа у того же слова не является основанием выбрать его вместо NUMR.
Закрытая проба проверяет, относится ли количественное слово к этой именной
группе. OTHER сохраняет исходные чтения, `?` блокирует неопределённую область.
Правила, слова, источник и решение входят в frozen trace. Другая грамматическая
форма требует отдельного покрытия ресурсов/конструктора, а не удаления слова.

У группы различаются внутреннее управление и внешняя роль. Исходное NOUN(gen,
plur) остаётся в R1 и `internal_readings`. Только внутри выбранного разбора
контекстная проекция получает внешний падеж из целого NUMR-чтения (nom/acc).
Число и род отдельного участника не выдумываются; собирательная группа допускает
согласование с единственным средним либо множественным числом сказуемого.
Роль группы всё равно проверяется обычной валентностью, T3/T4 и T5.

В «прошло несколько ливней»:

- актант события — один M, обозначающий упомянутую группу ливней;
- `M.meta.qualitative_group` хранит `membership_status=UNKNOWN`,
  `cardinality_status=UNSPECIFIED`, raw/source_range, head_ref/marker_ref,
  decision_ref, rule_id и resource_sha256;
- отдельный N с лексическим T «несколько» описывает тот же M через NOMINAL
  UsageLink; это не G(EXACTLY/AT_LEAST) и не числовое свойство;
- при отсутствии известного sense действует обычный OPEN_LEXICAL/UNLINKED.
  Каноническая количественная семантика не приписывается по написанию.

Это M с неизвестным составом, не K с перечисленными членами. Дедуп и отзыв
сохраняют общий SOM/NOMINAL-контракт: описание доступно через конкретный живой
путь источника и не получает собственной ROOT-опоры. Чтец обязан учитывать
описание группы, а не превращать её в один дождь или в произвольное число
дождей. При попытке перечислить такие M как численных свидетелей CountGoal,
COUNT по формуле и агрегат ENTITY возвращают UNKNOWN с
`QUALITATIVE_QUANTITY_NOT_NUMERIC`, без численных bounds. Пересчёт неизвестных
членов в точные экземпляры или согласование их с отдельным числовым утверждением
этот конструктор не выполняет; отдельный числовой путь без таких M не меняется.
Write boundary проверяет форму метаданных и запрещает одновременную подстановку
scalar_properties/implicit_participant. Запись группы, описания и ссылки —
в одном обычном fragment closure; повтор и recovery используют те же операции.

## Односторонняя временная граница

TemporalRules поддерживает `TEMPORAL_BOUND {rule_id, pattern, operator}`,
где operator = BEFORE/AFTER, а pattern содержит именованную группу `anchor`.
Это объявленная грамматика временной границы; произвольное «до существительного»
не становится часами. Для единственного согласованного совпадения формируется:

```text
TimeAssertion(target_ref = узел всей выбранной событийной области)
region = EXISTENTIAL(lo=null, hi=null)
expression = {
  kind: TEMPORAL_BOUND, status: SYMBOLIC, operator: BEFORE,
  raw: "До трех часов", source_range,
  boundary: {raw: "трех часов", source_range},
  expr_id, rule_id, resource_sha256
}
```

Числовое положение границы отсутствует. Год, часовой пояс, часть суток и точный
момент события не восстанавливаются из времени исполнения. Дата заголовка
остаётся отдельным CALENDAR_SCOPE того же пути. Локальная выраженная граница
сохраняется вместе с ней. «Вечером» остаётся NAMED_PERIOD без выдуманных часов.

Источник границы полностью покрывается временной зависимостью и не становится
вторым свободным scope-оператором. Другие/конкурирующие временные чтения требуют
разрешения области; их нельзя молча отбрасывать. Для уже распознанного CLOCK_RANGE
тот же TEMPORAL_BOUND может быть составной границей только при точном совпадении
source span и направления (AFTER/start, BEFORE/end); независимые совпадения
не подавляются. Запросы, требующие неизвестной числовой границы, дают UNKNOWN.

Write boundary проверяет точные spans/raw и включение anchor в выражение,
символический статус и отсутствие численных bounds. Свидетельство атомарно
записывается с опорой по существующему контракту TemporalLedger и сохраняется
при replay. Это хранение заявленного ограничения; общий числовой решатель
символических выражений здесь не объявляется реализованным.
