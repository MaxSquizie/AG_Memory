# Области модификаторов при координации

Дополнение V7 §4.7. Разрешённый разбор каждой клаузы не доказывает, что её
модификатор относится только к этой клаузе. Выбор общей области предшествует
assertion; ближайший глагол не является нормативным умолчанием.

## Закрытый набор структур

После композиции двух полных конъюнктов программа строит варианты:

- локальный scope: `AND(P, M(Q))`;
- общий scope: `M(AND(P,Q))`.

M — ранее построенный лексический модификатор с proposition-аргументом,
включая предложную группу. Это не список конкретных наречий или предлогов.
Слова, морфология, entity-актанты и исходные диапазоны сохраняются.
Scope над AND не заменяется двумя произвольными самостоятельными M-фактами.

Если у обеих клауз есть модификатор, сохраняются варианты локального
прикрепления, переноса каждого по отдельности и оба порядка вложения двух
общих модификаторов. Число вариантов проверяется **до** перечисления;
при превышении выпущенного max_candidates — COMPONENT_SEARCH_INCOMPLETE,
без выбора оставшегося префикса.

Короткая проба получает весь исходный фрагмент и закрытые метки готовых деревьев.
Модель не строит подграф. NONE_FIT/INSUFFICIENT_CONTEXT/MULTIPLE_ADMISSIBLE
не выбирают локальный вариант по умолчанию: весь enclosing fragment остаётся
неразрешённым, самостоятельный коммит конъюнктов запрещён.

Текущая реализация не объявляет полноту для n-арной координации с модификатором:
при трёх и более конъюнктах существует scope над собственной подгруппой.
Пока эти поддеревья не перечислены, результат —
COMPONENT_COORDINATION_SCOPE_INCOMPLETE. N-арный AND без модификатора этим
ограничением не меняется. Незамкнутые локальные клаузы и отдельная проблема
распределения временных выражений не обходятся новым механизмом.

## Поддержка и долговечность

Для `M(AND(P,Q))` O-опору получает только внешний M. При неизвестной
фактивности M конъюнкция и её операнды S-accessible, но не F-visible;
AND_ELIMINATION через M не лицензируется. Для выбранного локального варианта
обычные опоры AND и его конъюнктов сохраняются. Транзакция и отзыв — прежние
T5/T6/UsageLink/SupportLedger, нового писателя нет.

syntax_trace сохраняет candidate_id, дерево, исходные modifier refs и порядок
вложенности. Запрос уточнения содержит только JSON-данные (ID и подписи),
а не временные Python FrameCandidate. Перед сравнением с durable-записью
запрос приводится к JSON-представлению: tuple/array при replay не являются
изменением канонического содержания. Реальное несовпадение записи остаётся
INTEGRITY_ERROR.

Явный выбор из сохранённого запроса — declared clarification, новая версия.
Конструктор применяет выбранную альтернативу к замороженному T2-инвентарю,
проверяет тот же закрытый набор ID и только затем выполняет seal/T3–T6.
Повторное обращение не пересканирует источник для поиска новых кандидатов
и не оживляет отозванные опоры. Неявного выбора за пользователя нет.

Модули: coordination_scope.py (построение), coordination_clarifications.py
(применение сохранённого выбора); component_coordination.py — оркестрация.
Полнота всей грамматики и семантическая правильность отдельного ответа модели
этим контрактом не утверждаются.
