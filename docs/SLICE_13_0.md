# Slice 0.13.0 — каноническая наземная пропозициональная логика

## Назначение среза

Версия 0.13.0 закрывает цельный исполняемый контур пропозициональной логики для уже конкретизированных, то есть не содержащих свободных переменных, выражений АГ-памяти. Срез не вводит параллельную модель данных: атомарное утверждение остаётся `N`, а логическая композиция — зарегистрированным `g` поверх ссылок на `N/g`.

Архитектурная граница сохраняется:

```text
атомарный факт                  -> N
объектное отрицание             -> NOT(P)
явное опровержение конкретного N -> FALSE(N)
конъюнкция                       -> AND(A, B, ...)
дизъюнкция                       -> OR(A, B, ...)
условное правило                 -> IMPLIES(A, B)
```

`IS-A`, `FOLLOW` и `CAUSE` остаются отдельными обязательными структурными отношениями M2 и этим срезом не переопределяются.

## 1. `NOT(P)` и `FALSE(N)` теперь разведены в записи

Ранее естественно-языковое отрицание могло попадать в тот же `FALSE`, который используется механизмом исправления памяти. Это нарушало v4: содержание «сервер не работает» и мета-утверждение «предыдущее утверждение неверно» имеют разную семантику.

Теперь обычная отрицательная фраза интегрируется как:

```text
P = WORK(server)
NOT(P)
```

При этом внутренний `N`, представляющий `P`, может существовать как операнд формулы, но не получает самостоятельного factual occurrence только из-за того, что понадобился для построения отрицания.

`FALSE(N)` создаётся только явным контуром semantic correction/refutation и означает недопустимость конкретного ранее сохранённого утверждения как основания вывода.

Следствия:

- `NOT(P)` не удаляет и не переписывает `P`;
- `P` и `NOT(P)` могут одновременно храниться и образуют локализованный конфликт;
- повтор или новизна одной стороны не выбирают победителя;
- `FALSE(N)` остаётся адресным мета-опровержением конкретного UID.

## 2. Условные конструкции канонизируются в `IMPLIES`

Новые условные конструкции записываются как `IMPLIES(antecedent, consequent)`. Старое значение `IF` не используется для новых записей, но продолжает загружаться как совместимый псевдоним `IMPLIES` через `FunctionRegistry`.

Это сохраняет уже накопленные графы v0.12.x и одновременно делает новую запись однозначной.

Условные операнды остаются scoped propositions. Сам факт наличия `IMPLIES(P,Q)` не делает `P` и `Q` обычными утверждениями мира.

## 3. Ветви `OR` не материализуются как факты

Для фразы вида:

```text
В комнате Иван или Алексей.
```

каноническим asserted-content является `OR(A,B)`. Ветви создаются только как scoped operands и имеют `occurrence_count = 0`; обычный поиск фактов не имеет права считать их отдельно подтверждёнными.

Тем самым:

```text
OR(A,B) asserted
!= A asserted
!= B asserted
```

Это необходимо и для открытой семантики мира, и для дальнейшего корректного branch reasoning.

## 4. `FormulaGoal`

В inference-контракт добавлен отдельный тип цели:

```text
FormulaGoal(expression = Ref(N|G))
```

Он используется только для доказательства или опровержения конкретного уже канонически представленного выражения. Цель не принимает произвольный текст и не создаёт второй язык формул.

`InferenceEngine` передаёт такую цель в `GroundFormulaReasoner`.

## 5. `GroundFormulaReasoner`

Добавлен детерминированный решатель наземных формул. Он реализует общий proof path для `N/g`, не заменяя существующий relation reasoner.

Поддерживаемые операции текущего среза:

- asserted atomic `N`;
- `NOT`;
- `FALSE`;
- `AND`;
- `OR`;
- `IMPLIES`;
- modus ponens для наземных правил;
- устранение `AND` из утверждённой конъюнкции;
- сопоставление scoped-атома с единственным эквивалентным ordinary asserted `N`.

### 5.1. Открытая семантика мира

Отсутствие доказательства не становится отрицанием:

```text
не найден P -> UNKNOWN
```

а не `FALSE`.

`OR(A,B)` доказывается, если доказана хотя бы одна ветвь. Он считается опровергнутым только тогда, когда каждая ветвь формально опровергнута; наличие `UNKNOWN` не позволяет сделать этот вывод.

`AND(A,B)` доказывается только при доказательстве всех операндов. Явно опровергнутый операнд опровергает всю конъюнкцию.

### 5.2. Локализованный конфликт

Если одновременно доступны ordinary asserted `P` и asserted `NOT(P)`, цель не объявляется ни автоматически истинной, ни автоматически ложной:

```text
status = UNKNOWN
stop_reason = CONFLICTED
```

Это не вызывает логического взрыва и не мешает независимым доказательствам в других участках памяти.

### 5.3. Наземный modus ponens

Для:

```text
P
IMPLIES(P,Q)
```

решатель может доказать `Q` только если:

1. `IMPLIES(P,Q)` является действительно утверждённым внешним содержанием, а не вложенной/цитируемой гипотезой;
2. antecedent `P` формально доказан;
3. consequent соответствует текущей цели.

Многочастное условие представляется обычным деревом:

```text
IMPLIES(AND(A,B), C)
```

и срабатывает только после доказательства обоих оснований.

## 6. Scoped atoms и factual atoms

Операнд условной, дизъюнктивной, цитируемой или иной вложенной конструкции не используется как ordinary premise только потому, что он физически представлен `N`.

Для применения правила scoped atom может быть сопоставлен с ordinary asserted atom только при точном структурном совпадении шаблона и актантов. Если найден ровно один такой обычный факт, его доказательство становится поддержкой scoped operand. Неоднозначное совпадение не угадывается.

Это даёт нужное разделение:

```text
структура формулы существует
!= содержание её листа утверждено как факт
```

## 7. Поиск и возбуждение

Наземный reasoner не выполняет произвольный полный просмотр AH. Для переходов от текущей цели используются уже перестраиваемые индексы, в частности родители функциональных выражений для конкретной ссылки.

Если `InferenceAttention` передан в решатель, подтверждённые шаги формулы вызывают `focus(...)`. Поэтому доказательство может проходить через обычный Ignition/Workspace и не обязано быть «тихим» обходом структуры с нарисованной постфактум трассой.

Активация остаётся механизмом доступности и порядка внимания; она не является доказательством.

## 8. ProofSupport

Для наземного слоя используются структурированные основания вывода. Среди различимых причин:

- `FACT_ASSERTED`;
- `SCOPED_ATOM_MATCH`;
- `NOT_ASSERTED`;
- `EXPLICIT_REFUTATION`;
- `AND_ELIM` / `AND_INTRO`;
- `OR_ASSERTED` / `OR_INTRO`;
- `IMPLIES_ASSERTED`;
- `IMPLIES_MP`.

Это продолжает введённый в progress_03 принцип: trace отвечает на вопрос «как шёл вывод», а support — «от каких оснований зависит результат».

## 9. Что 0.13.0 намеренно не объявляет готовым

`FORALL` и `EXISTS` уже зарегистрированы, валидируются и могут сохраняться как канонические контейнеры, однако полноценное выполнение кванторов в этой версии не заявляется.

Причина архитектурная: для общего quantified inference необходимо подключить variable-bearing atomic predicate leaves к уже существующим `BoundVar` и `BindingEnvironment`, не создавая новый тип AH-узла и не вводя параллельное представление фактов. До закрытия этого контракта `GroundFormulaReasoner` возвращает для кванторных целей `UNKNOWN`, а не имитирует вывод специальным случаем.

Так же этот срез не меняет relation M2: `IS-A`, `FOLLOW`, `CAUSE` продолжают обслуживаться существующим rule-driven relation path и `InferenceSchemaRegistry`.
