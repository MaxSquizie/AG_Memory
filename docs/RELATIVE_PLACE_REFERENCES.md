# Относительное место и ссылка из последующего текста

## Представление

Направление движения и место — разные аргументы. Выпущенный лексический смысл может лицензировать неименованный пространственный актант: например, относительное место назначения при направленном движении. Такой M хранит исходное выражение и диапазон, source_tag, rule_id и resource_sha256. Его тип отношения — DESTINATION, LOCATION или ORIGIN; coordinates_status=UNKNOWN. Никаких географических координат, абсолютной высоты или тождества с одноимённым местом не возникает.

Одна исходная пространственная привязка имеет один occurrence-local M. Альтернативные структурные употребления того же исходного якоря не создают несколько мест. Разные исходные вхождения не сливаются по написанию. Само создание M не утверждает, что описанное движение произошло.

ProposalPolicy.spatial_references версии SOURCE_RELATIVE_PLACE_V1 связывает правила ANCHOR/REFERENCE с конкретными выпущенными R-S senses, POS и пространственной ролью R-V. Loader проверяет уникальность rule_id/sense_id, наличие лексического смысла и типизированной валентности. TemplateMap по-прежнему должен вести к реальному T текущей AH. Открытый предикат не получает каноническую пространственную семантику по одному написанию.

## Выбор ссылки

До structural_seal код готовит адресные якоря и варианты пространственных ссылок. Первый контур ограничен предшествующими якорями того же наблюдения внутри объявленного бюджета контекста. Пробы не создают кандидатов. На T4 из заранее подготовленного набора исключаются якоря, пространственный смысл которых не был разрешён. Отвергнутые варианты структуры и защищённые цитатные области не дают якорей этому контуру.

Короткая проба выбирает конкретный относительный якорь по исходному контексту. Даже единственный совместимый кандидат не выбирается автоматически. Недостаток контекста, отсутствие якоря и превышение бюджета не подменяются новым местом или ближайшим словом: фрагмент остаётся SPATIAL_REFERENCE_UNRESOLVED / SPATIAL_REFERENCE_SEARCH_INCOMPLETE. Эти исходы не означают отсутствия подходящего места во всей памяти.

Решение принадлежит исходному упоминанию и выпущенному правилу, а не отдельной копии frame. Перенос того же модификатора на всю координацию сохраняет одну привязку и не запускает второй вопрос о референте. Контекст вопроса адресует исходное предложение; область действия модификатора остаётся отдельным выбранным отношением.

Так, «Прогулку совершили вверх. Там катались…» допускает выбор относительного места назначения из первого предложения. «Там» становится ссылкой на этот M, а не синонимом «вверх». Его собственная область действия определяется уже выбранным деревом модификаторов: привязка не расширяет её на соседний конъюнкт.

## Запись и живость

Используются существующие ENSURE_ENTITY и SET_IDENTITY_BINDING. relative_place проверяется на write boundary, включая стабильный ID по полному описанию якоря. SPATIAL_ANCHOR связывает исходный якорь с M; SPATIAL_REFERENCE содержит тот же M, anchor_binding_ref и interpretation_decision_ref. При записи проверяется тип и живая исходная привязка.

Замыкание каждого использующего фрагмента содержит M и исходную привязку. Отчёт `plan\E` сохраняет общие структурные операции, когда хотя бы один допущенный фрагмент их использует. Это не перенос truth-support из исходного события: место может быть упомянуто без утверждения самого движения. Потеря одной опоры события при всё ещё действующей интерпретации его пространственного упоминания сама по себе не доказывает исчезновения места.

Отзыв исходного наблюдения инвалидирует обе привязки обычным каскадом. Явный отзыв SPATIAL_ANCHOR также делает SPATIAL_REFERENCE неэффективной и инвалидирует её; зависимые опоры теряют видимость. Указатель на мёртвую исходную привязку не заменяется другим совпадающим названием. Обычный run replay возвращает зафиксированное решение без повторной пробы. Declared clarification использует зафиксированные варианты и версию ресурса.

Пространственные M не попадают в нетипизированный список кандидатов на субъекта/личное местоимение. Чтение таких мест из долговременной памяти должно быть отдельным типизированным контекстным запросом через Ignition, а не глобальным поиском всех M.

## Границы реализации

Реализуется исходно-локальный пространственный binding внутри одного наблюдения. Извлечение якорей из произвольных предложных групп, выбор базиса «верх/низ», междокументное чтение через Ignition и ссылки через цитатные области этим контуром ещё не покрыты. Fixture содержит явно выпущенные TEST_ONLY словарные записи; это не утверждение полноты значений многозначных слов и не production release. Нового писателя, статусного журнала или механизма генерации графа моделью нет.
