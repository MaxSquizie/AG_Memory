# Относительное место и ссылка из последующего текста

## Представление

Направление движения и место — разные аргументы. Выпущенный лексический смысл может лицензировать неименованный пространственный актант: например, относительное место назначения при направленном движении. Такой M хранит исходное выражение и диапазон, source_tag, rule_id и resource_sha256. Его тип отношения — DESTINATION, LOCATION или ORIGIN; coordinates_status=UNKNOWN. Никаких географических координат, абсолютной высоты или тождества с одноимённым местом не возникает.

Одна исходная пространственная привязка имеет один occurrence-local M. Альтернативные структурные употребления того же исходного якоря не создают несколько мест. Разные исходные вхождения не сливаются по написанию. Само создание M не утверждает, что описанное движение произошло.

ProposalPolicy.spatial_references версии SOURCE_RELATIVE_PLACE_V1 связывает правила ANCHOR/REFERENCE с конкретными выпущенными R-S senses, POS и пространственной ролью R-V. Loader проверяет уникальность rule_id/sense_id, наличие лексического смысла и типизированной валентности. TemplateMap по-прежнему должен вести к реальному T текущей AH. Открытый предикат не получает каноническую пространственную семантику по одному написанию.

## Выбор ссылки

До structural_seal код готовит адресные якоря и варианты пространственных ссылок. Локальный контур использует предшествующие якоря того же наблюдения внутри объявленного бюджета контекста. Контур памяти добавляет только кандидатов из зафиксированного чтения активного workspace, описанного ниже. Пробы не создают кандидатов. На T4 из заранее подготовленного набора исключаются якоря, пространственный смысл которых не был разрешён. Отвергнутые варианты структуры и защищённые цитатные области не дают якорей этому контуру.

Короткая проба выбирает конкретный относительный якорь по исходному контексту. Даже единственный совместимый кандидат не выбирается автоматически. Недостаток контекста, отсутствие якоря и превышение бюджета не подменяются новым местом или ближайшим словом: фрагмент остаётся SPATIAL_REFERENCE_UNRESOLVED / SPATIAL_REFERENCE_SEARCH_INCOMPLETE. Эти исходы не означают отсутствия подходящего места во всей памяти.

Решение принадлежит исходному упоминанию и выпущенному правилу, а не отдельной копии frame. Перенос того же модификатора на всю координацию сохраняет одну привязку и не запускает второй вопрос о референте. Контекст вопроса адресует исходное предложение; область действия модификатора остаётся отдельным выбранным отношением.

Так, «Прогулку совершили вверх. Там катались…» допускает выбор относительного места назначения из первого предложения. «Там» становится ссылкой на этот M, а не синонимом «вверх». Его собственная область действия определяется уже выбранным деревом модификаторов: привязка не расширяет её на соседний конъюнкт.

## Запись и живость

Используются существующие ENSURE_ENTITY и SET_IDENTITY_BINDING. relative_place проверяется на write boundary, включая стабильный ID по полному описанию якоря. SPATIAL_ANCHOR связывает исходный якорь с M; SPATIAL_REFERENCE содержит тот же M, anchor_binding_ref и interpretation_decision_ref. При записи проверяется тип и живая исходная привязка.

Для локального якоря замыкание каждого использующего фрагмента содержит создание M и исходной привязки. Для уже закоммиченного якоря из памяти эти операции не повторяются: новый фрагмент создаёт только собственную SPATIAL_REFERENCE к существующим M и SPATIAL_ANCHOR, сохраняя исходный source_tag якоря. Отчёт `plan\E` сохраняет общие структурные операции, когда хотя бы один допущенный фрагмент их использует. Это не перенос truth-support из исходного события: место может быть упомянуто без утверждения самого движения. Потеря одной опоры события при всё ещё действующей интерпретации его пространственного упоминания сама по себе не доказывает исчезновения места.

Отзыв исходного наблюдения инвалидирует исходную и зависимые привязки обычным каскадом, включая ссылки из других наблюдений. Проверка живости учитывает статус наблюдения напрямую и не зависит от порядка обхода bindings. Отзыв только наблюдения со ссылкой сохраняет исходный якорь. Явный отзыв SPATIAL_ANCHOR также делает SPATIAL_REFERENCE неэффективной и инвалидирует её; зависимые опоры теряют видимость. Указатель на мёртвую исходную привязку не заменяется другим совпадающим названием. Обычный run replay возвращает зафиксированное решение без повторной пробы. Declared clarification использует зафиксированные варианты и версию ресурса.

Пространственные M не попадают в нетипизированный список кандидатов на субъекта/личное местоимение. Чтение таких мест из долговременной памяти выполняется отдельным типизированным контекстным запросом через Ignition, а не глобальным поиском всех M.

## Контекстный запрос к памяти

До structural_seal для каждого уникального пространственного упоминания/правила выполняется SPATIAL_REFERENCE через AttentionContextReader. Запрос включён в общий порядок чтения по исходным диапазонам вместе с REFERENCE/IMPLICIT_ARGUMENT. READ_TOKEN возбуждает выпущенные лексические символы; CONTEXT_GOAL продвигает объявленное число событий распространения существующего возбуждения, без искусственного seed нужного места. Только M из полученного workspace становятся допустимыми кандидатами. Тик не зависит от времени ответа модели.

Заменяемый индекс target_ref→SPATIAL_ANCHOR используется только для адресов активного workspace; само наличие записи в индексе не доказывает живость. Проверяются текущая привязка, её source_tag и опоры. Ограничение coreference_sources, если оно объявлено, дополнительно ограничивает источники. Из выбранных источников извлекается адресная короткая выдержка вокруг якоря; новая модельная переформулировка не создаётся. Выдержка и локальный контекст остаются данными пробы. Превышение бюджета числа кандидатов или суммарного контекста даёт SPATIAL_REFERENCE_SEARCH_INCOMPLETE без скрытого отбора первого места.

CONTEXT_READ атомарно сохраняет запрос, frozen rows, состояние внимания и result_hash. Обычный replay использует ту же запись, даже если память или активность затем изменились; новая интерпретация требует объявленного нового запуска. global_search_complete=false: пустое чтение не означает отсутствия места во всей AH. Выбор модели не определяет ни топологию, ни M, ни операции плана.

SPATIAL_REFERENCE к чужому наблюдению несёт context_read_hash. Write boundary проверяет стабильный binding_id, живую исходную привязку и подлинную CONTEXT_READ своего владельца run-binding: совпадают decision_ref, result_hash и пара entity_ref/memory_binding_ref в frozen rows. Неизвестная/несовпадающая квитанция → SPATIAL_CONTEXT_RECEIPT_INVALID. Старые опоры, M и source_tag не пересоздаются. Основание чтения P остаётся interpretation ground; отдельный факт получает собственную O-опору текущего наблюдения.

## Границы реализации

Реализованы исходно-локальная ссылка и чтение уже закоммиченных пространственных якорей из активированной AH между последовательными наблюдениями. Извлечение якорей из произвольных предложных групп, выбор базиса «верх/низ» и ссылки через цитатные области этим контуром ещё не покрыты. Один большой документ пока читается как одно наблюдение: автоматическая граница частичного коммита его областей ещё не реализована. Поэтому межнаблюдательный прогон не доказывает далёкую кореференцию внутри ещё не закоммиченной книги.

Fixture содержит явно выпущенные TEST_ONLY словарные записи; это не утверждение полноты значений многозначных слов и не production release. Нового писателя, статусного журнала или механизма генерации графа моделью нет.
