Провайдер отключён. Поэтому 640 языковых pipeline-кейсов этим прогоном **не проверены**; HTTP-маршрут и offline replay проверены отдельной регрессией с сервером фиксированных ответов. Эти цифры не оценивают качество локальной модели.

`comparison.json` сохраняет каждое расхождение с gold. В **35 FAIL-кейсах** среди расхождений есть отсутствующий путь экспорта наблюдений; они перечислены в `summary.json`. FAIL нельзя автоматически считать дефектом production-кода: требуется различить ошибку механизма, test fixture, экспорт checkpoint и ошибку gold. Ожидаемые значения не исправлялись ради прохождения.

Известные ограничения корпуса/привязки: отрицательные DSL-кейсы с невалидным исходным правилом блокируются до мутации; часть reference/migration/compound crash действий не подключена; точные комбинации бюджета перечисления ещё не имеют подходящей fixture. `bindings.json` и `runtime_coverage.json` позволяют увидеть доступность каждого кейса и механизма, а не только общий счётчик.

`actual.jsonl.gz` содержит фактические checkpoints и per-case manifests. `run_config.json`/`provenance.json` фиксируют точные исходные хеши; этот снимок остаётся историческим при изменении реализации. Публикуются агрегаты и фактические checkpoints; полные файловые WAL и resource fixtures остаются в каталоге выполнения runner, а не включаются в этот снимок.
