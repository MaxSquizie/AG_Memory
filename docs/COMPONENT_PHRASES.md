# Предложные компоненты: контракт и границы

Дополнение к §4.7 `FORMALIZER_ARCHITECTURE_V7.md`. Не меняет контракты
truth-support, identity, seal, admission или Ignition. Применяется только при
явно включённой ресурсной политике `ProposalPolicy.composition`.

## Построение

До seal программа распознаёт локальную форму `PREP ADJF* (NOUN|NPRO)`.
Каждый исходный токен сохраняет свои целые морфологические варианты. Предлог
и именная группа не сливаются в имя сущности. Согласованные определения входят
в lexical unit существующего именного якоря; новый исходный токен не создаётся.

Предложный компонент содержит `RELATION_TO_EVENT {component_id, anchor_refs,
source_range, preposition_ref, head_ref, status, role, children[]}` и дочерний
`ARGUMENT_CONTENT {anchor_ref}`. `BOUND` означает наличие структурной привязки
в данном кандидате, а не доказанную истинность события или разрешённый referent.

Для KNOWN-предиката разрешена только роль из его R-V с совпадающими
`allowed_preps` и падежом конкретного морфологического варианта дополнения.
Отсутствие `allowed_preps` не лицензирует произвольный предлог. Проверка повторяется
в T3 для каждого sense/valency: идентичные имена ролей не обходят ограничение.
`preposition_bindings` и выбранные whole variants входят в frozen frame/seal.

Если у токена предлога есть другие POS-разборы, даже единственная построенная
привязка требует положительной закрытой attachment-пробы. NONE_FIT,
INSUFFICIENT_CONTEXT, ошибка или исчерпание бюджета не разрешают её автоматически.
Непредложные словарные разборы остаются в TokenEvidence; этот локальный генератор
не объявляет исчерпывающую грамматику всех конструкций. Отсутствие подходящего
кандидата требует дальнейшей композиции/уточнения, а не выбора первого разбора.

## Непокрытое содержание

Неизвестному предикату не назначается каноническая роль по одному предлогу.
OPEN_LEXICAL не обходит отсутствующую R-V. Непокрытая группа сохраняет
`RELATION_TO_EVENT(status=UNRESOLVED, role=null)` и исходные токены в
`uncovered_token_refs`; весь фрагмент остаётся заблокированным.

Незаполненная обязательная роль R-V сохраняется в `missing_required_roles` и
`MISSING_REQUIRED_ROLE {gap_id, role, predicate_ref}`. Исключение — уже
лицензированный нулевой субъект (§4.7), у которого собственный контекстный цикл.
Объект или получатель автоматически не придумывается; пустой слот не удаляет
кандидат из IR. Выбор структуры/clarification не снимает блокировку непокрытых
токенов или обязательных ролей.

«После завтрака» без ресурсной лицензии остаётся относительным компонентом:
не появляется ни самостоятельное утверждение завтрака, ни точное время, ни
G(AFTER), выведенный только из похожего слова. Общая композиция относительных
временных событий и координации ещё не реализована этим расширением.

## Модули

| Модуль | Ответственность |
|---|---|
| `components.py` | Обход областей, координация этапов |
| `component_candidates.py` | Ограниченный перебор целых морфологических вариантов и ролей |
| `component_phrases.py` | Предложные группы, именные единицы, вложенные вопросы |
| `component_probe.py` | Закрытая проба и её интерпретационные основания |
| `component_participants.py` | Кандидаты неявных участников, контекст и разрешение цепочек |
| `component_policy.py` | Политика и совместимость морфологических признаков |
| `implicit_plan.py` | T5-операции для разрешённых неявных участников |

Новый писатель AH не вводится: материализация остаётся T6, отзыв — штатный
каскад. Тот же run replay не добавляет вторую опору. Короткие модельные ответы
выбирают готовые варианты; модель не генерирует графы/JSON структуры.
