# Именные зависимости в косвенных падежах

`nominal_dependency_cases` расширяет объявленный конструктор зависимостей
`CONSTRAINT_TREE_V1`. Для целого NOUN/NPRO-разбора в одном из этих падежей
создаются альтернативы `CASE_DEPENDENCY` с адресными именными хозяевами той же
области. Нужны отдельный sense в `dependency_senses`, R-S, R-V и TemplateMap с
реальным T текущей AH. Неполный ресурс отвергается загрузчиком.

Прямые роли сказуемого продолжают конкурировать с именными зависимостями.
Решение определяется локальной пробой по тексту и уже закреплённым связям;
совпадение падежа само по себе не доказывает зависимость. Ограничения запрещают
циклы и повторное занятие одиночного слота. Превышение бюджета не выбирает
первый вариант. GENITIVE и APPOSITION сохраняют собственные контракты.

`CASE_DEPENDENCY` фиксирует грамматическое дополнение существительного, без
догадки о владении, командовании, идентичности или иной канонической семантике.
Выбранные падеж и целый морфологический разбор сохраняются в evidence и повторно
проверяются при подготовке кандидата. Зависимость материализуется как структурное
NOMINAL-описание с отдельными актантами; самостоятельной truth-опоры не получает.
Определения зависимого существительного продолжают разрешаться обычным
механизмом согласования и выбора хозяина.

Для OPEN-предикатов TEST_ONLY-политика допускает творительный как непрозрачный
`SURFACE_ARG`, не как автоматически установленный INSTRUMENT или AGENT.
Для KNOWN-предиката по-прежнему требуется его собственная R-V. Загрузчик
принимает `abl` — обозначение творительного, фактически выдаваемое MorphProvider,
наряду с уже поддержанным `ins`; падежи разных чтений не смешиваются.

Расширение задаётся грамматическими категориями; леммы должностей, имена и
фразы дневника в runtime не перечисляются. TEST_ONLY fixture не является
reviewed production release.
