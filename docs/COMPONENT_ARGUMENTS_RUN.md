# Компоненты и неявные участники: первый контур

Дата: 2026-10-11. База до изменения: `5a207a360bad34adbc5777461cd1cb9bd83cc634`.
Норма: `FORMALIZER_ARCHITECTURE_V7.md`, §4.6–4.7 и операция EnsureEntity в §17.

## Что реализовано

- Программный генератор однопредикатных финитных клауз, в том числе с пропущенным субъектом. Политика `COMPONENTS_V1` закрепляется в reviewed resource release; без неё прежний контракт сохраняется.
- Согласованные прилагательные входят в именную группу. Исходные токены и целые морфологические варианты сохраняются. Нет правил по именам, фразам дневника или идентификаторам oracle.
- Неявная роль — адресный gap, не выдуманное слово. До seal фиксируются варианты локальных mentions, продолжения цепочек и неидентифицированных участников; контекстные чтения Ignition используют durable receipts.
- Короткая проба выбирает готовый вариант. Нельзя считать первого совместимого кандидата правильным или автоматически приравнивать рассказчика к автору/пользователю. При недостаточном основании фрагмент остаётся нерешённым.
- Разрешённый анонимный участник записывается как неназванный M. Несколько разрешённых привязок к одной цепочке переиспользуют M. Группа — непрозрачный M с UNKNOWN membership и нижней границей 2, без вымышленного списка участников.
- Запись проходит через обычные C/T5/T6, bindings и O-support; отзыв и recovery используют существующий журнал. Для повторного плана `reference_existing` определяется происхождением ссылки, а не наличием узла после первого коммита.
- Повторяющиеся местоимения имеют разные адресные IDs. Полный дневник выявил коллизию `ReferenceCandidate(«Она»)`; native-путь теперь использует token ID, поэтому одинаковые написания в разных позициях не сталкиваются на seal.

## Проверки кода

Две выборки: 49 passed и 36 passed, пересечение — 14 новых component-тестов; всего 71 уникальная прошедшая проверка. Покрыты запись/отзыв/восстановление настоящего AH, повтор со штатным ProviderAdapter без повторного транспорта и новых тиков, неизвестный состав группы, нерешённые привязки, scope-защита и opt-in release. Ответы в этих проверках scripted: они проверяют механизм, не точность модели.

Три отказа из старого `test_formalizer_native_production.py` отдельно воспроизведены на неизменённой базе `5a207a3`: ожидание записи без release и паритета с отключённым legacy-путём. Они не объявлены исправленными или зелёными. Один промежуточный GUI-прогон был прерван Qt при отсутствии `QT_QPA_PLATFORM=offscreen`; окончательная выборка запускалась с этой настройкой и прошла.

## Что ещё ограничивает чтение книги

1. Обстоятельства вроде «после завтрака», «вечером», сложная координация, control и вложенные области ещё не замыкаются этим генератором. Непокрытый материал сохраняется и блокирует фрагмент; он не отбрасывается для получения искусственного PASS.
2. Сохраняется общий лимит 8 LLM-проб на observation и ограниченные локальные наборы вариантов. Для большого документа нужен отдельный контракт распределения бюджета по зависимым областям, без молчаливого снятия лимита или недетерминированного продолжения replay.
3. Весь файл пока проходит как одно наблюдение с EOF-коммитом. Частичный frontier, своевременная фиксация событий и повторное открытие далёких зависимостей ещё не реализованы.
4. Полезность реальных модельных выборов, массовое разрешение неизвестных цепочек и production-ресурсы не доказаны этим проходом. Общая архитектура покрытием книги не объявляется завершённой.

## Запуск

К штатному диагностическому mailbox-запуску добавляется `--components`:

```bash
PYTHONPATH=src:. python -m tools.read_document_probe_mailbox book.txt --out data/document_runs/components_01 --development-fixture --components
```

Флаг создаёт новый явно TEST_ONLY release/hash. Это не подмена production-ресурсов. Для production `ProposalPolicy.composition` должен входить в соответствующий reviewed release; старый hash нельзя повторно подписывать как будто содержимое не изменилось.
