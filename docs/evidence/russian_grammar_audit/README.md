Провайдер заменён воздержанием на первом вопросе. В исходном прогоне 555 из 601 входа вообще не вызвали пробу, но только 18 разобрались без неё. У остальных отказ или остановка по времени также обходятся без вопроса. В базовом прогоне было 46 предъявлений, ноль полученных выборов и ноль сужений. Стоимость в вопросах на продуктивный выбор при нулевом знаменателе не определена. На контрольной фразе про Ивана один ответ «ушла» сократил число деревьев с двух до одного, «?» оставил оба, «0» отверг оба. В `Result.steps` для каждой предъявленной пробы сохранены число деревьев до и после и исход решения. Полезное сужение здесь — принятый ответ, после которого остаётся хотя бы одно дерево и число вариантов уменьшается.

Для UAS учитывается вершина каждого слова, кроме пунктуации, включая корень. Внутреннее направление связи между предлогом и именной вершиной приведено к представлению UD. Другие головы сохранены. Требуется полное совпадение токенизации предложения. Все 18 записей выровнялись. Так получается 94,7% на принятых записях. По отношению ко всем 9292 знаменательным и служебным словам корпуса правильно выдано 108 вершин (1,16%). Официальный показатель CoNLL 2018 использует собственные правила выравнивания и учёта пунктуации. [Методика CoNLL](https://universaldependencies.org/conll18/evaluation.html)

Смысловая ошибка — сохранено неверное отношение участника к действию либо неверный статус утверждения. Вручную сверены все принятые записи, включая совпавшие по UAS. У «Однако Мавроди успешно уворачивается от обвинений» все вершины совпали, но выбор вводного значения лишил сообщение статуса прямого утверждения. У фразы «Окончил отделение … университета Токай» память назначила университет участником действия. У записи «На юго-западе села живописный пруд» слово «села» стало подлежащим. Ещё в одной записи расходятся две синтаксические связи, смысловой ущерб спорен. Таким образом, ручная оценка одного проверяющего даёт 16,7% подтверждённых ошибок и 22,2%, если включить спорную запись. Зависимости UD сами по себе не дают эталона для истинности, модальности или соотнесения участников. [Решения по всем записям](review.tsv) · [Результаты по 601 входу](corpus.tsv)

## Граница записи

Проверка выполняется до открытия транзакции. Она проверяет заполнение обязательных позиций, указанных в таблице, падеж и вершину второго участника сравнения, предикативный падеж имени, переходность при прямом дополнении и словарное управление. Для возвратного «себя» у простой личной формы с единственным явным подлежащим сохраняется локальный участник, в том числе внутри чужой речи. При отсутствии установленной связи запись останавливается. Связывание притяжательного «свой» и контроль при инфинитиве требуют дальнейшей работы.

В таблице обязательных позиций приведены требования поддержанных конструкций сравнения, отрицательного наличия, эллипсиса и консервативная лексическая запись для «класть / положить». Для последней пациент засвидетельствован, в частности, в конструкциях FrameBank 4193 и 4194. Требование к отдельной записи в память принято проектом. Переходность сама по себе не требует явного дополнения, поэтому «Иван читает» проходит, «Иван положил» остаётся открытым, а «Иван положил книгу» записывается. Полнота словаря обязательных позиций пока не установлена. Для словарного предлога с неизвестным управлением положительный ответ модели больше не подменяет отсутствующее правило. [FrameBank](https://github.com/olesar/framebank) · [Таблица ограничений](../../../src/ah/russian_grammar/lexicon/required_arguments.tsv)

У «Иван выше Петра» уже на исходном коммите корнем было «выше», а «Петра» — вторым участником сравнения в родительном падеже. Отдельная регрессия подаёт повреждённое дерево прямо к границе записи и проверяет отсутствие изменений в журнале. При прогоне через окно чата запись правильного сравнения увеличила номер журнала с 0 до 1. После вопроса и после «Иван положил» номер остался 1. Тексты и последовательность наблюдений сохранены в [протоколе окна чата](gui.txt). [Исходный журнал трёх транзакций с контрольными суммами](gui.journal.jsonl) воспроизведён в новом экземпляре памяти. Запросы вернули «Петра» и «книгу», номер последней транзакции остался 3.

## Что происходит с продолжением

На входе «Иван сказал, что Мария ушла, а Пётр остался» отдельно запускался настоящий анализатор на каждом префиксе. Файл содержит прочитанный текст, число деревьев, общие для них связи и сформулированную пробу. Совпадение связи у всех полных деревьев одного префикса допускает пересмотр после продолжения. [Полная трасса](prefixes.jsonl)

| Последнее прочитанное слово | Результат |
|---|---|
| сказал | Одно дерево. «Иван» связан со «сказал» как подлежащее. |
| что | Ни одного полного дерева. Наружу не выдаётся состояние ожидания сказуемого придаточного. |
| Мария | Два дерева. Если здесь завершить ввод, предлагается проба о роли «Мария». |
| ушла | Одно дерево, проба исчезает. «Мария» связана с «ушла», а «ушла» — со «сказал». |
| а / Пётр | Полной структуры пока нет. |
| остался | Два дерева. Проба предлагает слова «сказал» и «ушла». |
| Конец ввода и выбор «ушла» | Одно дерево. Область сообщения включает «Пётр остался». Только теперь происходит запись. |

Внутренний разбор простой клаузы по очереди расширяет префиксы. Внешний вход получает законченную строку и собирает полные деревья. Он не переносит состояние от одного поступившего слова к следующему. Повторные вызовы в этом эксперименте показывают, когда появляется и снимается неопределённость. Потоковая инкрементальность остаётся открытой задачей.

## Язык проб и источники

В шести изолированных запусках GPT-5.6 Luna на минимальном уровне каждой модели предъявлялся один вопрос, по одному запуску на язык и пример. Одинаковы исходные слова и порядок вариантов. Переведены вопрос, управляющая инструкция и пояснения к ответам.

| Объект выбора | Английская проба | Русская проба |
|---|---|---|
| К какому сказуемому присоединено «остался» | ушла | ушла |
| При каких действиях «воду» является дополнением | Скопирована строка «? — The sentence leaves the choice unclear.» | пил |
| Какие действия выполнила Анна в «написанное и подписанное Анной» | написанное и подписанное | написанное и подписанное |

В первом случае допустимы оба присоединения. В последнем подпись указана явно, а авторство первого действия допускает разные чтения. Английский ответ про воду выражает воздержание, но нарушает протокол точного выбора одного ключа. Ни превосходство одного языка, ни качество Jev на этих шести запусках установить нельзя. Официальный API принимает состояние и именованные типизированные вопросы. Для Choice он возвращает выбранный ключ, распределение вероятностей и показатель уверенности. Ключа доступа к провайдеру в этом запуске не было. [Контракт System One](https://docs.typesafe.ai/api/system-one.md) · [Choice](https://docs.typesafe.ai/primitives/choice.md)

Проверены 22 исходных уникальных внешних адреса из документа о русской грамматике. Для части учебных страниц прямой запрос вернул 403, для одного большого PDF текст не загрузился. В таких местах ссылки заменены проверяемыми разделами, включая описание разнесённой количественной группы в НКРЯ и § 134 академического справочника о прямой речи. Страница ВШЭ о главе «Относительные придаточные» подтверждала библиографию, но не конкретную интерпретацию примера. В документе теперь отдельно указаны языковое правило и проектное решение о хранении двух ссылок.

Copestake, Flickinger, Sag и Pollard (2005) описывают представление семантики и недоопределённости. Hough, Kennington, Schlangen и Ginzburg (2015) формулируют требования к пошаговой обработке для диалога. Обе работы задают основания для сравнения подходов. Реализация AG_Memory проверяется трассой выше. В документе модуля не обнаружены ссылки с `utm_source=chatgpt.com` или ссылка на обобщённый бинарный поиск. [MRS, 2005](https://www.cl.cam.ac.uk/~aac10/papers/mrs.pdf) · [IWCS, 2015](https://aclanthology.org/W15-0125/)

## Остальные замечания о правилах

Для сравнения, однородных сказуемых и относительных придаточных в шести падежах есть воспроизводимые положительные примеры в тестах модуля. Временная и уступительная части в «Когда Анна пришла, Иван ушёл» и «Хотя Анна пришла, Иван ушёл» пока получают одну общую метку обстоятельственной связи. Разбор «Иван устал, так что остановился» оставляет выбор открытым. Подтверждены фактические ограничения:

- У «Иван увидел себя» и во вложенном «Мария сказала, что Иван увидел себя» ссылка теперь ведёт к Ивану. «Иван передал свою книгу» ещё не разбирается. Для «его» сохраняется возможность внешнего владельца.
- В «Анна передавала книгу» словарь дал более одного глагольного чтения. До снятия омонимии действие не записывается. Сам по себе несовершенный вид не решает, было ли достигнуто завершение.
- «Никто не пришёл» сохраняет отрицание. «Ни Анна, ни Олег не пришли» и «Не только Иван, но и Анна пришли» остаются без полного дерева.
- «Дверь открылась» записывается, «Пусть Иван уйдёт» не разбирается. Форма на -ся сама по себе не определяет смысловую роль деятеля.
- «Пришли двое» разбирается. «Большинство студентов пришло» записывается, а «Большинство студентов пришли» ошибочно определяется как побуждение. Для таких форм нужны одновременно допустимое смысловое согласование и выбор наклонения.
- «Иван, открой окно» распознаётся как побуждение. Вводное «вероятно» в предложении «Анна, вероятно, ушла» сохраняет неуверенность при ответе на прямой вопрос. Ошибку с «однако» показывает корпус.

## Критерий следующей проверки

Предлагаемые пороги для второго русского корпуса с заранее замороженной разметкой и политикой ответов: завершённый разбор как минимум 90% допустимых входов, UAS не ниже 95% на принятых деревьях, верхняя односторонняя 95%-я доверительная граница для доли ложных записей не выше 1%. Для последней метрики вручную размечаются случайно отобранные записи, спорные решает второй проверяющий. При нуле ошибок точная биномиальная граница достигает порога начиная с 299 проверенных записей. Для режима с моделью отдельно публикуются число вопросов, доля воздержаний и число вопросов на успешное сужение. Эти числа предложены для принятия решения командой. Текущий результат пороги не проходит.

## Воспроизведение

Из корня проекта с установленными зависимостями:

```sh
git clone --depth 1 --branch r2.15 https://github.com/UniversalDependencies/UD_Russian-GSD.git /tmp/grammar-gsd
PYTHONPATH=.:src python scripts/measure_russian_grammar.py /tmp/grammar-gsd/ru_gsd-ud-test.conllu /tmp/grammar-results.json
PYTHONPATH=.:src python scripts/trace_russian_grammar_prefixes.py 'Иван сказал, что Мария ушла, а Пётр остался.'
PYTHONPATH=.:src python -m pytest -q tests/test_russian_grammar*.py
```

Число тестов относится к конкретному набору файлов. На исходной версии нового модуля было 202 успешных проверки, после изменений — 207. Отдельно на исходном коммите повторены три файла старого формализатора: `test_formalizer_component_phrases.py`, `test_formalizer_component_predication.py`, `test_formalizer_modifier_forest.py`. Получено 39 падений и 4 прохождения. Идентификаторы всех 39 падений совпали с прежним протоколом. Например, для «Покатались на шлюпках» старый генератор вернул `STRUCTURE_NOT_COVERED`, запись не состоялась. Результат нового набора не свидетельствует о прохождении старого или всего репозитория.
