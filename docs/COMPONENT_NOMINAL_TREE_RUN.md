фрагментам; это не метка полной формализации документа.

## Как вопросы закрыли конкретную остановку

В предложении о сообщении программа предложила закрытые варианты хозяина:

- «в штабе» → ситуация;
- «об австрийском инженерном искусстве» → сообщение;
- согласованные определения → искусство (связанные морфологические варианты).

Затем обычная проверка выбирала целиком построенную композицию. Модель
не писала JSON, подграф или роли от себя. В T5/T6 получились основной узел,
модификатор ситуации и три именных описания. ENTITY-слоты остались Ref(M).
NOMINAL-links соединяют описание «об» с сообщением и оба определения с
искусством. Описания S-only: дополнительных AddRootSupport на них нет.
Лексические OPEN/UNLINKED-связи сохраняют текстовую структуру; фактивность
внутренней ситуации автоматически не выводится из неизвестного модификатора.
Час 06:30/18:30 и дата остаются неразрешёнными, как в источнике.

## Долговечность фактического результата

Финальный код повторно выполнил тот же абзац с точным воспроизведением
записанных транспортных запросов/ответов; несовпавший запрос привёл бы к
CAPTURED_PROBE_MISSING. Это не выдаётся за новый ответ модели.
Отдельно выполнен native replay той же пары observation/version:
запросы 9→9, тики 56→56, batch/фрагменты/ledger неизменны.
Хеш ledger до и после native replay:
`9c8f9a24e453ba9cc6d01e86effe7dbaa62bc2adba97f3548a47ef70a806e2f7`.

На копии фактического журнала восстановлен новый AH, отозван source_tag:
F-visible 3→0, S-accessible 10→0, NOMINAL-links SUPERSEDED. Ещё одно
восстановление из этого журнала совпало с состоянием после отзыва.
История сохраняется; отдельного придуманного графа для проверки не было.

## Что остаётся

Первое препятствие в двух непройденных предложениях — **ранний предел
build_clause: больше трёх именных кандидатов → COMPONENT_SEARCH_INCOMPLETE**.
Новый слой вопросов пока находится после построения этой базовой рамки.
Следующий необходимый шаг — перенести декомпозицию/вопросы к именным зависимостям
до комбинаторного перебора; простое увеличение предела проблему не решает.
Дополнительно требуются общие конструкторы голого генитива, приложения и
составного предлога: «игры Алексея», «доклад Макарова», «министр юстиции»,
«во время». Особые правила под эти слова не добавлены.

Запросы с NOMINAL-ограничениями пока получают QUERY_NOMINAL_SCOPE_UNSUPPORTED;
нельзя отбросить уточнение и ответить на более широкий вопрос. Нужен отдельный
query matcher таких описаний. Не заявлены семантическая полнота открытых T,
качество локальной модели или завершение всей книги.
