# F05 / F06 / F14 — завершение перечисления и смысл множественности

29 октября 2026. Изменения runtime; подтверждения ниже сценарные, без живой LLM.

## Исправленная причинная цепочка

Раньше EMPTY создавался отдельным Decision с перечнем отвергнутых страниц только в строке STRUCTURAL_TASK. Его domain_ref не указывал на TASK_DOMAIN. licensed проверял page_refs только у TASK_DOMAIN, поэтому отзыв отрицательной страницы не отзывал разрешение использовать EMPTY. Исходный свидетель сохранён в check_empty_retirement.py как исторический материал, его старые утверждения больше не являются acceptance текущего кода.

Теперь каждый завершённый результат, включая EMPTY и пустой генератор, имеет TASK_DOMAIN. Его page_evidence связывает точный набор кандидатов, поддержанные варианты, исход страницы и отпечаток решения/зависимостей. При завершении проверяются все страницы; смена источника/входа родителя или отзыв страницы во время обхода блокирует публикацию итога. При последующем чтении licensed и valid_domain проверяют те же основания. Проверяются также отрицательные страницы положительного выбора: уникальность среди предложенного домена зависит от них.

Смена ответа по прежнему адресу тоже не сохраняет старое свидетельство: одного совпадения decision_ref недостаточно. Новая идентичность итогового домена включает свидетельства страниц. Независимый домен при отзыве не теряет разрешение.

Место механизма — общий сборщик перечисления. Именно здесь известны все страницы и факт исчерпания iterator. Отдельная страница не вправе закрыть домен; поздний потребитель не должен восстанавливать список просмотренных страниц по догадке. Полученное свидетельство относится исключительно к переданному генератору.

## Контракт множественности

| Граница | Представление | Разрешённый смысл |
|---|---|---|
| JSON_V1 / SELECT_LABELS_V1 | SelectionResponse.multiplicity | ALTERNATIVE_READINGS; несколько вариантов одного вопроса |
| Прямая native-проба | DirectProbeInputs.multiplicity | Только альтернативы; совместный режим отклоняется |
| Выбор очередной единицы | SelectionPurpose.NEXT | Альтернативные следующие шаги, не добавление всех сразу |
| Подтверждение разбиения | SelectionPurpose.CONFIRM | Ровно одно предъявленное отношение |
| Удержание неоднозначности | SupportedDomain + valid_domain | Только домен альтернативных прочтений с живыми страницами |
| Сбор исходного материала | CollectionReceipt | COMPATIBLE_OCCURRENCES; совместный набор вхождений |
| Завершённый именной/временной инвентарь | FUNCTION_INVENTORY + completed | COMPATIBLE_FUNCTIONS; не набор альтернатив одного вопроса |
| Уточнение равных reading-доменов | reading_clarifications.project | Тип альтернатив + проверка свидетельств в frozen generation |

CollectionReceipt различает завершение ALL_AVAILABLE_OCCURRENCES и NO_SUPPORTED_ADDITION. Во втором случае обязательна живая отрицательная completion_proof. Сохранены исключённые вхождения и все исходные proofs. Полнота выбранного набора не превращается в полноту всех разбиений. Повторное использование указателя содержания проверяет это свидетельство, а не только наличие строки SOURCE_SET.

Для остальных непосредственных потребителей MULTIPLE_ADMISSIBLE просмотрены component_predication (удержание альтернатив), composition_tasks и component_refinement (ожидание/неполнота), refinement_uncertainty (явно маркированное policy assumption), implicit_introduction (неизвестная идентичность группы без вывода членов), component_probe (сведение только по установленному тождеству референта). Последние два механизма не превращают список ответов в совместных участников. Политика refinement остаётся отдельной F16.

## Доказательства и пределы

- check_enumeration_evidence: реальные choose/codec; отзыв каждой из двух страниц EMPTY и положительного выбора; изменение ответа на том же адресе; отзыв во время последней страницы; пустой iterator; альтернативы; frozen generation; независимый домен остаётся доступным.
- check_source_collection_receipts: разрывный набор, два вида завершения, исключения, несколько альтернативных начал, отзыв отрицательного завершения.
- check_selection_purpose: тип операции в ключе/proof, cardinality подтверждения, ? на странице, отличия next-step от совместного набора; одинаковая семантика JSON и числового кодека; запрет подмены типа инвентаря.
- Дополнительно: prerequisites (включая синтетическую цепь 1200 receipts), selection boundary, direct contracts, nominal chain, structural inputs, lexical boundary contracts. Реальные сценарные прогоны: обычный/вложенный PARTIAL без записи, три content-reference contrasts, OOV contracts.
- В check_partial_readings исправлена десериализация тестового Ground: восстановлен объект вместо dict. Ожидания смысла и допустимости записи не менялись. Синтетический depth-fixture получил явные страницы и доменные свидетельства; прежняя искусственная строка без TASK_DOMAIN больше не лицензируется. Legacy proof без такого свидетельства не обходит проверку.

**F14:** установленный дефект лицензирования EMPTY исправлен в общем механизме и проверен. Это не утверждение, что уже скопированные результаты всех потребителей транзитивно очищаются: инвентари и снимки остаются F07/F12.

**F06:** типы и потребление множественности native closed-choice контура согласованы на перечисленных границах. Это не доказательство правильности ответов модели и не изменение политики owner-first/F15 или assumption/F16. Структурные генеративные и naming/open-set протоколы остаются отдельной F08.

**F05 остаётся открытой:** теперь итог доказывает только корректное завершение конкретного перечисления. Не доказана языковая полнота ScopeLexicon, соседних именных групп, refinement, quantifier/spatial/reference генераторов и объединения их маршрутов. Нельзя пометить их полными на основании этого изменения. Лексические ресурсы/признаки по-прежнему требуют анализа как ограниченные генераторы; расширение их языковой области и представимости не заменяется новой меткой результата.

Достаточность изменений локальная: при неизменных входах и сохранённых ответах можно проверить, что весь переданный кандидатный набор обработан и исход не потерял оснований; тип не позволяет представить альтернативы как совместный набор. Семантическая корректность исполнителя и полнота самого набора — независимые предпосылки.
