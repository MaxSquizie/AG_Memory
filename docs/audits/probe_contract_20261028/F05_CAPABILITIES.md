## Сквозное обязательство каждого ID

Для каждого применимого ID фиксировать producer, точный typed payload/witness, всех consumer, наблюдения кеша (включая отсутствие), resume, historical проверку в исходной ветви, понижение выбранной ветви и durable отзыв. Неприменимость этапа обосновывается; пустая ячейка не означает закрытие. P01–P04/P19 задают общий слой, но их локальная реализация не закрывает перечисленные маршруты автоматически.

Источники: GRAMMAR, COMPONENT/LEXICAL, структурный producer, исходные ENTITY/GROUP/GROUP_MENTION/MENTION/PLACE, ACTIVE_MEMORY; контекст reader и морфологические гипотезы имеют собственное происхождение, а не являются доказанной семантикой. Полнота объединения доказывается отдельно для каждого объявленного producer.

Targets/участники: терминальный M, закрытый K, ссылка NOMINAL_REFERENCE, зависимый GROUP_MENTION, PLACE, bound variable, proposition/action content, temporal interval, open narrative group. Фактическая поддержка участников группы сейчас ограничена terminal/reference; перенос остальных типов в общий путь — обязанность P18, а не утверждение, что они уже работают. Семантика group-valued/repeated identities там, где отсутствует в архитектуре, требует ответа пользователя.

## Границы статической полноты

RELATIONS сверяется с AST словаря: все 20 пунктов имеют R-ID. 12 conditional shell contracts сверяются отдельно; LEXICAL не приравнен к готовому staged producer. Шесть блоков сопоставлены F05_STATUS §§1–6. Source/target реестр получен из nominal_reference_domain, nominal_reference_source/local/memory/chain, nominal_group_source, bound_references, content_reference_functions и поздних narrative/temporal consumers.

Динамические границы остаются непокрытыми до адресованных проверок: compose_child callback; reader.read/fork/checkpoint и historical verifier; lexical issuer private invocation; provider selector/replay; native persistence emit/revoke. Реестр не объявляет статически обнаруженный вызов достижимым и не выдаёт отсутствующий вызов за доказанный дефект. Их владельцы: C-CHILD, C-CACHE, C-HISTORY, C-DURABLE; P10/P19/P21/P22/P23.

Проверка P00 не включала live Luna/local-model и не доказывает достаточность prompt для слабой модели. Перед итоговой P23 необходимо испытать именно окончательный wire text с изолированным исполнителем.
