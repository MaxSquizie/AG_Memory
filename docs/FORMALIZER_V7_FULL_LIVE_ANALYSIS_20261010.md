# Полный языковой прогон V7: причины отказов и границы исправлений

Проверен запуск `gui_20261010_163134_42874821`: 640 языковых кейсов, LM Studio, `qwen3.8-27b-nvfp4-q5k-no-mtp`, reasoning off, timeout 240 s, max_tokens 4096. Источник — предоставленные `gui_stats(1).json`, `gui_report(1).md`, `progress(1).jsonl`. Исходный код для контрольного исполнения — `b464b0c2b65e17caa5482a52b9444ff9fa3c86c0` ветки `temp`.

## Фактический результат

**273 PASS / 367 FAIL / 0 BLOCKED**, все 640 кейсов завершены. Исключений исполнения нет. Все 640 HTTP-вызовов завершились SUCCESS/200; каждый полный raw response сообщает `reasoning_output_tokens=0`. Прежние нарушения `head_anchor` и отсутствующей роли не повторились. A31/A33 проходят. Этот результат не означает прохождения архитектурных ворот.

## Исправления

### Общая политика OPEN и её экспорт

В 95 кейсах утверждения AH/IR/journal уже совпали с gold; FAIL вызван только пустым `/open/capabilities`. Exporter читал необязательное поле `Hypernode.meta.inference_capabilities`, которое writer не создаёт. Реальная query-механика уже ограничивала UNLINKED exact-attestation.

Добавлена единая read-only `node_inference_policy`: UNLINKED разрешает только `EXACT_ATTESTATION`. Её используют query eligibility, запрет canonical derivation, default OpenTemplate и oracle exporter. Политика не создаёт truth support, не связывает OPEN с известным смыслом и не меняет N/G, роли, scope или живость. Проверены запросы с точным workspace/актантами и отрицательные случаи без excitation, с иной лексикой, переставленными ролями и иным NOT-scope. Непроверенные capability-флаги не расширяют право вывода.

### Запрос TP получает ограничения действующего релиза

В цитатной группе по case_id 105 кейсов: 103 FAIL / 2 PASS. В 94 есть `ATTITUDE_UNKNOWN`. На 98 proposition-рёбрах этой группы модель выбрала `ATTITUDE/SURFACE_ARG`; для SAY действующий релиз требует `OBJECT:PROPOSITION`, и AttitudeMap также привязан к OBJECT. Две успешные LANG-цитаты используют OBJECT. В отдельных ответах связь с содержимым вовсе отсутствует или дочерний предикат имеет неверную роль.

Раньше TP видел только общий enum ролей. Теперь bounded request содержит все совпавшие с региональными lemma/POS и объявленными multi-anchor patterns альтернативы R-S/R-V: типы слотов, роли, падежи, предлоги, кардинальность; отдельно AttitudeMap и совпавшие TemporalRules. Данные привязаны к хешу и версиям resource snapshot. Semantic sense IDs, canonical T/Ref и gold не передаются. Альтернативы не выбираются заранее; превышение ограничений явно останавливает запрос, вместо отправки произвольного префикса.

Metadata вопроса берётся из объявленного request и валидированных QUERY_INTENT. Вопрос о формуле не означает WH-gap. Старый поверхностный детектор «что» не выдаётся модели за доказательство вопросительной структуры. Временные триггеры несут исходные anchors, а не автоматически выбранного владельца даты.

`SURFACE_ARG` не переписывается в OBJECT. Ответ с неверной ролью остаётся отказом, даже если запрос содержит подходящий R-V. Строгий валидатор не ослаблен. Эффект нового промпта на модель требует нового live-прогона.

### Исправления TEST_ONLY фикстуры

| Дефект | Исправление | Граница |
|---|---|---|
| TIRED требовал wire EXPERIENCER для именительного субъекта «устал» | R-V wire SUBJECT отображается в канонический EXPERIENCER | Production role resolver и gold не меняются |
| Привязка известной сущности задана только для токена; ENTITY `[PREP,noun]` имеет другой mention ID | Фикстура заранее объявляет carrier для двух соседних anchors `[PREP, объявленная сущность]` | Произвольные составные mentions не привязываются по голове; production identity fallback не добавлен |
| ScopeLexicon требовал IMPLIES для всякого «если», включая «если бы» | Взаимно исключающие декларации IMPLIES и COUNTERFACTUAL | Это данные общей конструкции; существующий generic scope validator проверяет ответ |

На 47 записанных ответах, затронутых первыми двумя дефектами, результат изменился с 0 PASS / 47 FAIL на 42 PASS / 5 FAIL. Старый ответ A14 с IMPLIES после исправления декларации не переписывается: получает PROPOSAL_INVALID и не коммитится. Никакие новые смыслы для пропущенных nonfinite/control-конструкций в этом проходе не добавлялись.

### Диагностика и GUI

TP-ответ только с ENTITY/TIME, из которого не получается ни frame, ни логический корень, теперь явно несёт STRUCTURE_NOT_COVERED. Его структура сохраняется для аудита; такой вариант не исчезает ради уникальности соседнего допустимого варианта. Он не превращается в факт.

В GUI завершённый запуск, результаты которого взяты из `case_finished`, больше не подписывается «Partial run». Завершённость определяется `run_finished` и количеством завершённых кейсов; источник сравнения указывается отдельно. Исходные 273/367 не пересчитываются при рендеринге.

## Повторное исполнение сохранённых ответов

Контроль: все 640 **неизменённых** видимых ответов повторно поданы в исходный настоящий T0–T6 и свежую AH. Gold удалён из stimulus перед вызовом binder; только внешний checker сравнивает результат после исполнения. Получены ровно исходные **273 PASS / 367 FAIL**, все 640 ответов потреблены по одному, непредусмотренных запросов и исключений нет.

На исправленном коде и фикстуре тот же набор ответов дал **410 PASS / 230 FAIL**: 137 прежних FAIL закрылись, все 273 прежних PASS сохранились. Исключений и непредусмотренных запросов нет; ровно 640 ответов потреблены, неиспользованных ответов нет. Новые PASS: 95 OPEN-кейсов с единственным дефектом экспорта и 42 LANG-кейса с исправленной фикстурой. Новый промпт не превращает старый ответ в другой ответ модели.

В 33 оставшихся OPEN-кейсах есть дополнительные ошибки структуры/роли или abstain; исправление policy export само по себе не материализует отсутствующий допустимый OPEN-узел. Остались лишь три FAIL без native-диагностики: A06 (restriction и лексическая модель), LANG-02-3-before_point (PARTIAL, пропущенные часы) и NONFINITE-04-base (отсутствующий DESIRE sense и неверная структура инфинитивного содержания).

**142 целевые проверки прошли**, включая настоящий local HTTP seam, T0–T6/store, policy read restrictions, TP wire/evidence и GUI progress/report. Независимое ревью подтвердило отсутствие production-веток по конкретному предложению/case_id/gold, подмены ролей и автоматического identity для произвольных составных mentions. Проверка новых evidence limits по всем 640 исходным входам: COMPLETE 640/640, LIMIT_EXCEEDED 0, максимум 4344 байта evidence, 60 шагов поиска, 7 альтернатив. Валидатор корпуса по-прежнему сообщает CORPUS_VALID: 2542 кейса / 10902 проверки / 118 механизмов / A01–A39 / DR1–DR31; это проверка корпуса, не исполнение всех его кейсов.

Это counterfactual повторное исполнение provider bytes на изменённом коде/фикстуре, а не новый ответ модели и не journal replay старого запуска под другим хешем исходников. Обычный CLI replay сохраняет строгую проверку совпадения исходников/корпуса. Записанные неверные роли, abstain и ошибки scope не исправлялись автоматически.

## Что остаётся

| Механика | Фактическая проблема | Что нужно |
|---|---|---|
| Цитаты и proposition arguments | SURFACE_ARG вместо released OBJECT, пропущенное ребро, незакрытый дочерний аргумент | Проверить новый bounded prompt на локальной модели; семантическое уточнение допускается только с полной ресурсной лицензией и трассой |
| Номинальная координация A02 | AND с ENTITY-операндами запрещён; текущий frontend не замыкает группу актантов | Общая типизированная OP5/group-композиция, отдельно от логического AND пропозиций |
| Control/phase/impersonal | A35 и часть nonfinite: агент инфинитива не связан; ряд нужных смыслов/конструкций отсутствует в fixture | Объявленные конструкции control и фазового содержания с доказуемой привязкой; не догадка «первый субъект» |
| Ограниченная квантификация A06 | Модель потеряла STUDENT-restriction; форма FORALL проходит проверку | Generic проверка объявленных restriction/precedence constraints. Нельзя требовать IMPLIES у каждого FORALL без лицензии |
| Discourse A11 | Модель не предложила EXISTS/BIND для «кто-то… он» | Общая структура и дискурсивная привязка; не преобразование каждого NPRO в новую сущность |
| Временной scope | В 47 temporal mismatches records пусты: 32 без frames, 13 с разобранным временем при другом блокирующем отказе, 2 без диагностики | Сохранять TIME_SCOPE и незамкнутый attachment; не прикреплять дату ко всему предложению |
| Boolean queries | QUERY_SLOT на служебном «что»/«Верно ли» создаёт несуществующий SURFACE_ARG-gap | Развести request modus и положительно доказанный WH/count-gap |
| Лексическая модель A06 | Fixture PASS_EXAM требует THEME=exam, gold ожидает AGENT-only | Независимо согласовать лексическую единицу «сдать экзамен»; не удалять актант в exporter |
| Доказательство полного покрытия | Alignment/source_range может засчитать неиспользованные cues как покрытые | Проверять замыкание типизированных зависимостей и разрешённых служебных конструкций; численный охват span не доказывает смысл |

Сам факт валидного JSON/типизированного графа не доказывает правильную интерпретацию исходной речи. A06 показывает это даже при FULL_CANONICAL. Поэтому оставшиеся FAIL нельзя целиком списывать на «плохую модель»: есть пробелы frontend-композиции, ресурсного контракта, coverage evidence и отдельное несоответствие fixture/gold. G0–G5 здесь не переводятся в PASS.
