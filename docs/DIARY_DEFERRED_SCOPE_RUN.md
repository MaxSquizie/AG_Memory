# Дневник: неопределённость области, член группы и мягкая граница

Продолжение после `cc2285d`, по уточнениям пользователя от 12 октября 2026. Использован прежний неизменённый фрагмент за 27 июля `[94447,94814)`. Общий SHA256 исходного дневника: `e1f39d7f418121ce5956be9410f058a14ef76f82c88a113df42570f5511d8e71`. Это фактические прогоны исходного текста на TEST_ONLY_COMPONENTS, не корпусные тесты и не production/G5. Новые тестовые файлы не добавлялись.

## Исполнено

- Сохранён короткий ответ `?` о хозяине «прибывших», полный набор совместимых альтернатив и вопрос человеку. При AVAILABLE первый фрагмент остаётся неразрешённым. При явно объявленном UNAVAILABLE применяется политика минимального вложенного набора: дочери, без Аликс. Это `ASSUMED_UNRESOLVED`, не новый смысловой ответ модели.
- В графе встречи сохраняется K «Аликс + дочери», а описание прибытия использует M дочерей. NOMINAL-link содержит проверяемую проекцию через `host_group_ref` и `host_member_binding_ref`; первоначальная проверка равенства целой группы дочернему участнику больше не блокирует легитимный случай. Прибытие остаётся S-only; время сохранено внутри его описания.
- Внутренняя заглавная у возможного личного глагола формирует только кандидата границы. Независимая проба подтвердила SPLIT перед «Обедал»; источник не редактировался. Это доказательство выбранного разделения, а не полного разбора обеих областей.
- Контракт леса и ориентира закреплён в архитектуре: отдельный объект леса, пространственная связь к церкви, последующее именование того же объекта при подтверждённой идентичности. Автоматический общий механизм позднего именования этим проходом не объявляется завершённым.

## Проверенный жизненный цикл

| Ситуация | Наблюдаемый результат |
| --- | --- |
| Канал AVAILABLE, ответ пробы `?` | 1 фрагмент APPLIED: завтрак; оба хозяина описания сохранены в запросе |
| Канал UNAVAILABLE | 2 фрагмента APPLIED: первое предложение и завтрак; выбран минимальный охват, на link записана группа неопределённости |
| `ignore_clarification` для актуального вопроса | Durable migration, версия 2; 2 фрагмента APPLIED, reason=IGNORED; ответ человека не выдуман |
| Поздний выбор всей группы через `clarify` | Версия 3, прежний link SUPERSEDED, новое описание на целой K без scope_assumption; повтор вызова не меняет ledger |

**Последняя строка — диагностически заданный ответ через публичный API, а не утверждение автора дневника или вывод из источника.** Она проверяет заменимость допущения. Результат чтения источника с недоступным уточнением — именно минимальный охват «дочери» со статусом ASSUMED_UNRESOLVED.

В этой цепочке обнаружена и исправлена прежняя ошибка восстановления календарного решения: преобразование словарей в объекты Ground мутировало JSON-запись для следующего clarification snapshot. Теперь восстанавливаемый Decision отделён копированием от неизменяемой записи. Позднее уточнение и повтор проходят сериализацию.

Проверены на полученном графе: native replay без новых вызовов/тиков и изменения ledger; fresh recovery; отзыв наблюдения; отзыв binding дочерей; отзыв только описания. При отзыве binding зависимый первый фрагмент закрывается, завтрак остаётся; отзыв только NOMINAL-link закрывает прибытие, сохраняя фактические корни. Все результаты после восстановления совпадают. ## Ограничения

Полной формализации записи ещё нет. Сохраняется выбор хозяина «в лес», грамматика относительного «который…», а отделённое «Обедал и провел вечер…» ещё не даёт полного самостоятельного коммита. Разделение не подменяет разрешение ролей и контекста. Формализация открытых лексических конструкций остаётся UNLINKED.

Игнорирование вопроса — явное событие хоста; произвольный таймер по физическому времени не добавлен. API и CLI подключены, интеграция действия игнорирования во все варианты GUI не заявляется.
