## Текст по слайдам

### Титул

Первая демонстрация показала, как предложение становится фактом: алгоритмы сужают варианты, языковая модель отвечает только на узкий вопрос, вывод идёт по IS-A, FOLLOW, CAUSE. Сейчас — что добавлено в архитектуре памяти, чтобы этот контур не развалился на корпусе, в диалоге и при шуме. Предметная область — *[DomainLine]*.

### Пять схем первой презентации (~3 мин суммарно)

1. **БЯМ только после сужения.** Текст не отдаётся модели целиком. Морфология и синтаксис собирают кандидатов. «Он» — инженер или датчик? Модель выбирает из двух, затем INSTALL и CHECK связываются FOLLOW. Это уже не RAG.

2. **Морфология сужает роли.** «Старший инженер проверил сигнал датчика в серверной»: падежи и границы групп отсекают SUBJECT=сигнал и LOCATION=датчик *до* семантики. К probe уходит короткий список.

3. **Два типа узкого вопроса.** Кореференция («кто он?») и граница события («эвакуация — отдельный факт?»). После ответа — канонические узлы, не свободный текст.

4. **Дискурс.** Неоднозначность сначала *фиксируется* (UNRESOLVED), потом изолированный запрос, потом RESOLVED и разбор продолжается. Нет тихого угадывания по ходу текста.

5. **Возбуждение ≠ доказательство.** «Почему эвакуация?» Цель CAUSE(?, эвакуация). Серые узлы рядом возбуждены, в ответ входят только рёбра, прошедшие правило.

### Где кончается демонстрация

Локальный контур закрыт. Не закрыты: куда факт живёт дальше, как не отдать историю модели, как не оставить полуграф, как кореференция на десять абзацев, как забывать сирот и не вырезать живое, как честно сравниться с векторным поиском. Это уже спецификация разработки, не формула монографии в чистом виде.

### Три слоя

Каноническая AH — что помнится. Runtime — возбуждение, Workspace, proof, временные DiscourseRef. Main LLM — генератор, не писатель памяти. Монография: что помнить. Мы: как это не сломать моделью.

### Полный поток

После probe — atomic Integration в AH, ignition, Workspace, recall/proof, проекция, ответ, запись ответа только в H. Generation не есть confirmation. Нет окна чата: если факт нужен, он должен быть возбуждён.

### Atomic Integration и fail-closed

Раньше риск: модель допишет слот, в графе останется обрубок. Теперь commit целиком или ничего. Равноправные кандидаты — явная группа неоднозначности. Это то, из-за чего роли на опечатках и эллипсисе не превращаются в ложные факты.

### Отложенная кореференция

На схеме с «он» якорь в том же предложении. В документе якорь позже. DiscourseRef не узел памяти. «Кто-то / он» — одна формула существования, не фейковая персона UNKNOWN. Иначе корпус наполнится мусорными сущностями и оборвёт цепи вывода.

### T/N vs L, без keyword-trigger

Новый глагол — шаблон и факт, не новое системное ребро. IS-A, FOLLOW, CAUSE умеет reasoner. «Если» само не делает IMPLIES. Иначе граф становится словарём союзов, а не структурой, по которой можно сделать три шага на защите.

### Формализация: какой тип

Алгоритмы уже дали клаузы и актанты. Модель отвечает на один закрытый вопрос. «Установил» → install → T_INSTALL и факт N. «Иван — человек» → не новый глагол, а IS-A по listed referents. Python пишет UID, не модель.

### Формализация: квантор и импликация

«Все люди» — не сущность m_все_люди. Вопрос: NONE / EXISTS / FORALL / NOT_FORALL. FORALL даёт правило HUMAN → MORTAL, не список людей. «Если» только cue: спрашиваем направление subordinate→matrix, затем g_IMPLIES. «Не все пришли» и «все не пришли» — разные деревья. UNCLEAR не пишется в память.

### Lexical Recovery

Схема 2 предполагает нормальные словоформы. Зашумлённый вход — отдельный слой до семантики. Чат-модель слово не чинит. Неуверенное исправление не идёт в identity. Тогда морфологическое сужение ролей с первой демонстрации работает и на опечатках.

### Workspace вместо чата

Рабочая область — все элементы с возбуждением выше порога, не top-N чанков. Модель получает проекцию этой области и результат proof. Поэтому она не «помнит диалог» и не подменяет граф цитатой из исходника.

### Proof через такт

Картинка 5 уже говорит: релевантность помогает найти, доказывает правило. Добавляем: каждый шаг proof — обычный такт ignition со сдвигом Workspace. Нельзя обойти граф поиском и потом нарисовать красивый след. Пустая трасса UID = вывода не было.

### Жизнь и GC

Время первоначальной жизни — иммунитет, не автоудаление. Пульс ритма не считается жизнью, иначе сироты вечные. Живое с якорем в S не вычищается возрастом. После автоматического наполнения корпуса граф остаётся рабочим: и для такта, и для трёхшагового вопроса.

### RAG снаружи, шаблоны внутри

Исходный текст — provenance. Векторный baseline — отдельный пакет, в AH не пишет. Один парсер с жёсткими T и обязательными субъектом/объектом на малой и на большой модели. Слабая модель меньше выдумывает слоты не потому что «умнее промпт», а потому что слоты уже заданы каркасом.

### Регламент

Покажем новый факт с UID, вопрос на три шага с трассой тактов и смену одного гиперпараметра. На экране должно быть видно то же, что на последней исходной схеме, но уже как состояние памяти, а не как картинка из PowerPoint.
