# Локальная проверка формализации

## Запуск на Windows с LM Studio

Нужен Python 3.12 или новее. В корне репозитория установите GUI-зависимости в
своё окружение (однократно):

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[gui]"
```

В `config/lmstudio.toml` укажите адрес локального сервера и точный ключ модели
в `llm.lmstudio_base_url` / `llm.lmstudio_model`. Запустите сервер LM Studio,
затем `run_formalizer_lab.bat`. В GUI нажмите **Start**, если backend ещё не запущен.

При первом запуске создаётся `artifacts/formalizer-lab/gui.toml` с копией
настроек backend, отдельной сохраняемой AH и текущим профилем композиции:
именные зависимости, рекурсивные дети, модификаторы, области документа,
пространственные ссылки и нечисловые FORALL/EXISTS. Ресурсы явно
`TEST_ONLY`: это доступный стенд проверки, не полный словарь русского языка.
Числовые кванторы и новая арифметика отложены.

Повторный запуск использует **ту же** тестовую память. Для смены модели после
подготовки меняйте `artifacts/formalizer-lab/gui.toml` через настройки GUI или
редактор. Не подменяйте релиз ресурсов внутри уже использованного журнала.
Новый профиль/чистую сессию создавайте в новой папке:

```powershell
.\.venv\Scripts\python tools/prepare_formalizer_v7_gui.py --config config/lmstudio.toml --out artifacts/my-review-session --profile composition
.\.venv\Scripts\python -m ah.gui.app --config artifacts/my-review-session/gui.toml
```

На Linux используются те же Python-команды с путём к своему интерпретатору.
Обычные `run_gui*.bat` продолжают использовать настроенную память/ресурсы.
Инспектор работает и в обычном GUI; отдельная память не является условием
работы логического вывода.

## Проверить вход

1. Откройте **Документы** на панели инструментов.
2. Выберите `.txt`, `.md`, `.markdown` или `.docx`, либо вставьте фразу, вопрос
   или полный текст в поле ввода. Нажмите **Разобрать файл в AH** / **Разобрать
   текст в AH**. Это настоящий V7-конвейер с записью допущенных фактов в текущую
   AH. Вставленный текст проходит тот же документный маршрут без ответа Agent.
3. Следите за стадией, числом проб и бюджетом. По окончании нажмите **Проверить
   разбор…**. Для обычного чата та же кнопка **Проверить последний разбор…**
   находится в панели LLM; она явно открывает последний завершённый снимок.

Каждая попытка создаёт новую папку `document_runs/<дата>_<id>` внутри данных
сессии. Там лежат исходный файл, декодированный текст, `report.json`,
`interpretation.json`, `regions.json`, `progress.jsonl`. Повтор неизменённого
входа использует native replay; новый каталог отчёта не означает повторную
запись фактов. Ошибка чтения документа сохраняется как STOPPED без выдуманного IR.

## Что проверять в инспекторе

| Раздел | Для чего |
|---|---|
| Формулы | Дерево операторов и связанных переменных; переход к лексическому фрейму |
| Границы условий | Начало/конец цельной области, владелец, токены, области операндов и контроль сохранности |
| Фреймы | Предикат, аргументы, роли, морфологические привязки и причины структурного отказа |
| Морфология | Исходная словоформа и сохранённые варианты чтения |
| Решения | Кандидаты, выбранное значение, основания, точный запрос и сырой ответ модели |
| Пробы | История component-проб, включая заменённые вопросы и исходные ответы `?` |
| Трасса | Capture-домены grammar, ограничения, scope-слоты, дочерние проекции и этап отказа |
| Без привязки | Токены без структурного якоря; это повод посмотреть источник, не автоматическая ошибка |
| Контекст | Реальные адресные чтения и основания из памяти |
| Привязки | Итоговые ссылки и связанные переменные, включая пропущенных участников |
| Граф AH | Фактически записанные узлы, операнды и актанты; обход от ссылок receipt, без глобального просмотра памяти |
| Результат | Native receipt: что действительно допущено, какие фрагменты и узлы записаны |

Выбор записи подсвечивает её диапазон в исходном тексте. Связанные ID доступны
в нижнем списке: **Перейти к связанному объекту**. Поиск работает по ID,
названию и статусу, список разбит на страницы по 150 записей. Большие исходники
показываются окном вокруг выделенного диапазона; полный текст остаётся в
снимке. JSON-предпросмотр ограничен, экспорт не обрезает выбранный снимок.

`APPLIED`, отсутствие диагностик и успешный replay **не являются оценкой
смысловой точности**. Сопоставляйте формулу с исходником: общий ли субъект,
правильно ли стоит NOT, целиком ли охвачена координация, нет ли утверждения тела
под модальностью/квантором. Candidate и структура сами по себе не факт.

## Сохранить замечание и передать разбор

Выберите запись, задайте «Ошибка», «Неточность», «Нужна проверка» или
«Проверено вручную», опишите наблюдаемое и ожидаемое и нажмите **Добавить
замечание**. Затем **Экспорт разбора и замечаний…** сохраняет один JSON со всем
снимком, source SHA256, observation/structural ID, моделью/backend и замечаниями. До экспорта
замечания существуют только в открытом инспекторе.

Файл можно открыть через **Открыть сохранённый…** без запуска модели.
Экспорт — материал для диагностики; он не меняет AH, не служит журналом replay
и не отправляется куда-либо автоматически. Для разбора ошибки передавайте этот
JSON; в нём содержатся исходный текст, память, реально прочитанная при разборе,
и запросы модели из снимка. Если остановка случилась до IR, открывайте `report.json`.

## Текущая граница реализации

Цельные условия защищены от изменения/потери при последующей композиции и перед
seal. Неполное определение исходных границ, сложного restriction, общего субъекта
или кореферентности остаётся видимым в решениях/диагностике. Инспектор помогает
находить эти случаи; он не объявляет их автоматически исправленными.


Проверенный пример текущего этапа: «Не каждый студент может сдать экзамен и
получить диплом». При подтверждённых локальных выборах получен один корень
`NOT(FORALL(v, STUDENT(v) → POSSIBLE(AND(сдать(v, экзамен), получить(v, диплом)))))`.
Оба действия используют одну связанную переменную. «Получить» в данном TEST_ONLY
релизе остаётся OPEN_LEXICAL; конкретное словарное значение не выдумывается.
Повторный прогон проверен через native replay. Это проверка исполнения с внешними
ответами на закрытые пробы, а не измерение качества вашей локальной модели.
