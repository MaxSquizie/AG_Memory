# Обстоятельства общего события

Ресурсный режим `ProposalPolicy.composition.modifier_scope=SHARED_EVENT_V1`
расширяет `QUESTION_TREE_V1`. После выбора целых морфологических чтений и
именных хозяев конструктор перечисляет области оставшихся модификаторов события.

Для двух модификаторов A и B перечисляются три структуры:

- A(B(P));
- B(A(P));
- AND(A(P), B(P)), где обе ссылки P ведут к одной рамке и одному узлу содержания.

Вложение лексических модификаторов не считается коммутативным. При большем
числе компонентов перечисляются разбиения на совместные описания и рекурсивные
вложения. Каждый исходный модификатор употреблён один раз, листья используют
общую рамку P. Перестановки операндов AND канонизированы. Превышение
`max_candidates` блокирует весь поиск (`COMPONENT_SEARCH_INCOMPLETE`), успешный
префикс не выдаётся за полное множество. Этот контракт не утверждает полноту
всех способов выражения обстоятельств в языке.

Короткая закрытая проба выбирает связи из программно построенных альтернатив.
Если не различаются роли, морфология и именные зависимости, предъявляются
только различающиеся scope-связи. Общность P указана явно; модель не генерирует
граф и не создаёт ещё одно событие. Неопределённый ответ сохраняет отказ.

## Материализация и фактность

`component_scope_tree` хранит обычное типизированное дерево `frame_ref/AND`.
Рамка-носитель этой метаинформации остаётся лексическим узлом: её ID нельзя
подставлять вместо всей области. Пропозициональный аргумент переносит дерево,
а именное уточнение сохраняет дерево описания и проверяемый путь к хозяину.
Верхняя область материализуется единственным фрагментом T5/T6; выбранные
операнды не выходят отдельными root-фактами.

Для параллельного случая корень AND получает O-опору; его конъюнкты — обычные
производные опоры AND_ELIMINATION. Это не лицензирует P через неизвестный
лексический модификатор: UNKNOWN UsageLink остаётся структурным. Независимое
утверждение P требует собственного основания. NOMINAL-описания, binding,
отзыв и recovery работают с тем же общим содержимым.

Отвергнутые целые альтернативы остаются в Decision/рамках для аудита, но не
исполняются как ещё не разрешённые фрагменты и не порождают фиктивные ошибки
пропущенных участников.

## Ограничение межклаузной координации

Подъём ветвящейся области через отдельную конъюнкцию клауз пока требует
расширения перечислителя общей области. `COMPONENT_COORDINATION_SCOPE_INCOMPLETE`
запрещает подменить её одной цепочкой от рамки-носителя. Это отдельная граница,
не основание отбрасывать соседние ветви или угадывать их scope.

Модули: `modifier_scope_shapes.py`, `component_nominal_tree.py`,
`component_scope_contrast.py`, `native_plan.py`, `refinement_host_path.py`.
