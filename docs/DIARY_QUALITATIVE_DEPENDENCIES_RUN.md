# Дневник: качественное количество и временная граница

Фактическое чтение записи за 28 июля после `1192c55f58b5464dd09173661bc120c11c550711`.
Использован прежний canonical journal после уточнённого 27 июля; внимание при
восстановлении стартует холодным. Никакие имена и ожидаемые графы из oracle
не передавались. Ресурсы остаются **TEST_ONLY**; G0/G5 не оценивались.

## Результат на полном исходнике

Вход — неизменённые 291 символ записи, SHA256
`f30e1e69e6a3f150721996fbaba091cdc0d23c336eb3e4202ae07d9539bd4889`.
Селектор получил 22 закрытых вопроса и ответил только числовыми метками/`?`.
После ограничения согласования группы окончательный код повторно прочитал
тот же источник через **точное воспроизведение записанных запросов/ответов**:
новый или отличающийся запрос не имел запасного ответа. Это воспроизведение
транспорта отдельно от проверенного native replay.

проходе с исправленными границами клауз — два. Это число коммитов, **не метрика
полноты или семантической точности**. OPEN-лексика не объявляется найденным
каноническим смыслом только из-за успешной записи.

## Отдельная проверка временной записи на источнике

Для отделения времени от следующего именного препятствия взят точный непрерывный
фрагмент `[160,185)` той же записи: «До трех часов отправились». Он не заменяет
прогон полной записи и не доказывает разрешённость отсутствующей части.

Фрагмент закоммичен обычным T5/T6: один событийный узел и TimeAssertion с
`TEMPORAL_BOUND / BEFORE`, raw «До трех часов», boundary.raw «трех часов»,
`status=SYMBOLIC`, `EXISTENTIAL(lo=null,hi=null)`. 03:00/15:00 и дата не придуманы.
Неявный SUBJECT — неизвестная группа; автор/его спутники не назначались ей
по умолчанию. Для этого короткого фрагмента вызов селектора не понадобился.

В обоих запусках native replay подтвердил отсутствие новых provider calls,
тиков Ignition и изменений canonical ledger, равенство batch hash и committed
fragments. Свежий AHStoreAdapter восстановил те же состояния из журналов.
Числовой запрос проверен на восстановленном AH; чтение не изменило ledger.

## Реализованные границы и следующий останов

Новые механизмы вынесены в `qualitative_quantity.py`,
`qualitative_group_entity.py` и `symbolic_temporal_bounds.py`; существующие
конвейер, NOMINAL, writer и replay используют их через небольшие подключения.
Словарь и регулярные выражения находятся в ресурсе, не в алгоритме.

Текущий количественный конструктор покрывает соседние NUMR + NOUN(gen, plur)
с объявленными лексемами. Массовые существительные, составные точные числительные
и все возможные формы количественных групп этим проходом не закрыты.
Символическая временная запись не является числовым решателем календаря.

Следующий конкретный разрыв: PREP + указательное определение + частица + NOUN
в «к тому же месту». Сейчас конструктор PP теряет цельную группу из-за частицы,
поэтому до полноценного контекстного разрешения «тому же месту» не доходит.
Нельзя исправить это выбором ложного RECIPIENT для «месту».
