# Композиция клауз, относительное время и бюджеты проб

Дополнение архитектуры V7 §4.6–4.7. Программа строит кандидатов, ссылки и план;
модель отвечает только коротким выбором из закрытого множества.
Новых правил по именам, словам дневника или конкретным предложениям нет.
Политики и лексические триггеры поставляются ресурсным release.

## Пробы по исходным окнам

Опциональный `ProposalPolicy.probe_budget`:

```json
{"version":"SOURCE_WINDOW_V1","window_tokens":64,"calls_per_window":24,"tokens_per_window":16384}
```

Значения выше — диагностический TEST_ONLY fixture, не production-рекомендация.
Лоадер валидирует диапазоны. Окна образуются из исходных токенов T1 до проб;
расход относится к окну якоря решения. Изменение контекста или переход T2→T4
не обнуляет расход. Число кандидатов не создаёт новых окон/нового бюджета.
Для всего источника предел равен сумме фиксированных лимитов окон.

ProviderAdapter учитывает расходы по тем же окнам. Существующий runtime-предел
токенов ограничивает каждое окно сверху. Счётчик — детерминированная оценка
`max(1, (len(prompt)+len(response))//4)`, не точное число токенов модели.
Сверхлимитный полученный ответ расходуется и отклоняется; следующий запрос не
получает потраченный бюджет повторно. RECEIVED/FAILED воспроизводятся из журнала.
Схема окон и активный ключ входят в provider params_hash: replay в другом окне
даёт INTEGRITY_ERROR. COMPUTATION_LIMIT не переименовывается в неоднозначность.
Без политики сохраняется прежний observation-wide бюджет.

Окно бюджета не является смысловым блоком, новым наблюдением или границей
истинности. Контекст, Scope/RegionForest, Ignition и admission сохраняют свои
контракты; устаревшие frozen runs не получают новую политику задним числом.

## Конъюнкция

`composition.coordination_operators=["AND"]` и выпущенный connective ScopeLexicon
лицензируют кандидата из нескольких полных финитных клауз. Дочерние CLAUSE
сохраняют исходные диапазоны и токены. Каждая клауза сначала закрывает свои роли;
затем отдельная проба подтверждает asserted-конъюнкцию.

Опущенные участники не становятся одинаковыми из-за союза: identity разрешается
отдельно. T5/T6 создаёт единый AND-фрагмент, прямую опору корня и производные
AND_ELIMINATION. Ни одна дочерняя клауза не может коммититься самостоятельно,
если хотя бы один компонент или enclosing scope не разрешён. Отзыв корня убирает
производные пути; восстановление использует обычный store-журнал.

Текущая реализация сохраняет блок для цитат, вопросов, отрицания и иных
неподдержанных enclosing scopes, общего времени и общих аргументов конъюнктов.
Отказ одной композиции не разрешает отбросить её связь и утверждать остаток.

## Именной относительный временной якорь

`ScopeLexicon` объявляет `attachment_kinds=["TEMPORAL_NOMINAL"]`,
operator BEFORE/AFTER/DURING и `restriction_pattern.anchor_cases`.
Конструктор сопоставляет целые морфологические варианты PREP + NOUN, сохраняет
WHEN_RELATION → EVENT_ANCHOR с исходными ссылками. Закрытая проба подтверждает
отношение; она не генерирует календарную дату или граф.

T5 планирует occurrence-local OPEN event-anchor N без root-support,
G(operator, [событие, якорь]) и канонические OPERATOR UsageLinks для Ref(N|G).
Событие и явно высказанное отношение получают собственные O-опоры в одном
фрагменте; якорь остаётся S-only. TimeAssertion возникает только из независимо
лицензированной датировки, не из слов «после/до». Независимость/равенство двух
якорей по написанию не предполагается.

Known-существительное без пригодной схемы не превращается в OPEN.
Модифицированный якорь, несовпадающий падеж, конкурирующие интерпретации одного
якоря и неразрешённая область сохраняют отказ вместо усечения содержания.
Это первый конструктор, не полный анализ всех обстоятельств.

## Анонимный субъект без дублирующих гипотез

Для одного пропуска есть один кандидат нового неидентифицированного участника,
scoped к источнику и gap. «Центр повествования» не создаёт параллельную сущность
или альтернативу с тем же содержанием. Анонимность не утверждает неравенство
известным людям и не идентифицирует автора, загрузившего файл или пользователя.

Существующие mentions, предыдущие gap-цепочки и обоснованные кандидаты памяти
остаются отдельными возможностями. Только выбранная CHAIN/MEMORY переиспользует
M. Ни пол/число, ни первый подходящий кандидат не лицензируют автоматическое
слияние. Неопределённый выбор сохраняется. Для группы неизвестен состав;
«отправились» не означает автоматически «рассказчик и предыдущий объект».

## Модули

| Модуль | Ответственность |
|---|---|
| `probe_windows.py`, `provider_budget.py` | Источник окна и транспортный расход |
| `component_clause.py` | Одна клауза, подготовка закрытого вопроса |
| `component_coordination.py` | AND и блок неполной композиции |
| `component_temporal.py` | Исходные относительные группы |
| `relative_time_plan.py` | Обычные T5-операции относительной связи |
| `component_participants.py` | Подготовка и разрешение анонимных цепочек |

Новых писателей памяти и обходов T5/T6 нет. Проверка этих механик не повышает
G0/G5 и не доказывает полную формализацию книги.
