# Slice 0.12.99 — детерминированный контракт функциональных символов `g`

## Цель

Закрыт обязательный контракт архитектуры v4: функциональный символ `g` может существовать в канонической AH только тогда, когда его `g.ID` зарегистрирован и имеет детерминированную машинную семантику. Реестр является метаданными кода, а не памятью и не источником истины.

## Реализация

Добавлен общий `ah.logic.FunctionRegistry`. Проекционный слой больше не владеет семантикой функций; прежний импорт из `ah.projection.function_registry` сохранён как совместимый фасад.

Базовый реестр содержит:

- `AND`;
- `OR`;
- `NOT`;
- `FALSE`;
- `IMPLIES`;
- `FORALL`;
- `EXISTS`.

Старый `IF` зарегистрирован только как совместимый псевдоним `IMPLIES`, чтобы уже сохранённые графы v0.12.x оставались загружаемыми.

Каждая запись реестра фиксирует:

- допустимую арность;
- проверку формы операндов;
- обработчик вывода;
- человекочитаемую проекцию;
- совместимые псевдонимы.

## Каноническая граница

`AHCore.add_function`, `AHCore.ensure_function` и редактирование существующего `FunctionSymbol` теперь валидируют `g.ID` через `FunctionRegistry`. Неизвестный `g.ID` не может быть записан в AH случайной строкой.

При загрузке дампа persistence повторно проверяет зарегистрированность и форму каждого `g`; повреждённый или неизвестный функциональный символ отклоняется до выдачи рабочего `AHCore`.

`BoundVar` остаётся неузловым scoped descriptor. Для `FORALL/EXISTS` на этом срезе закреплён внешний контейнер `(BoundVar, body_ref)`; конкретная семантика атомарных шаблонов с переменными не изобретается сверх архитектуры v4 и будет подключаться отдельным шагом.

## Совместимость

- `IS-A`, `FOLLOW`, `CAUSE` не изменены.
- Существующие `AND/OR/FALSE/IF` из parser/integration продолжают загружаться.
- `IF` получает семантику `IMPLIES`, но старые UID и сериализованное значение не переписываются автоматически.
- Никакой новый canonical node kind не введён.
