# Дневник: утверждённость событий и ссылка на неизвестное место

Проверка после `3d819ab73492954e20963db7814e7d6277b4e1ef`.
Использован реальный исходный текст дневника, TEST_ONLY release и независимые
короткие пробы. Модель не строила JSON или подграфы. Это не прогон локальной
модели и не доказательство полной формализации дневника. Статусы ворот не менялись.

## Сделано

- Добавлен общий выбор области исходного утверждения под лексическим
  модификатором. Положительный выбор создаёт обычный O-grounded фрагмент;
  отрицание/цитата/модальность не обходятся автоматически.
- Именная ссылка может адресовать уже введённое неименованное место.
  Локальный якорь и чужая квитанция Ignition проверяются раздельно.
- Уточнение передаёт Ignition в новую интерпретацию. Кандидаты собственной
  заменяемой версии не становятся основаниями новой версии.
- Исправлен обнаруженный на реальном прогоне отказ
  `NOMINAL_REFERENCE_RECEIPT_INVALID`: tuple морфологических оснований в
  памяти и JSON-list сравниваются по полной канонической сериализации.
  Подмена содержимого ограничения по-прежнему отвергается.

## 28 июля

в [машиночитаемом свидетельстве](evidence/diary_source_assertions.json).

данного пользователем уточнения «совместные действия» — новая версия,
APPLIED, 14 фрагментов и шесть выбранных областей утверждения.

Проверена F-видимость событий «принял», «приехали», «поехал», «отправились»,

не остались исключительно структурными операндами. Для чая и обеда
использован существующий AND_ELIMINATION. Рассказчик один; две групповые
привязки сохраняют группу с рассказчиком и неизвестным остатком участников.

Проверены: повтор без новых проб/тиков/изменения ledger, восстановление из
журнала, отзыв версии с потерей видимости её узлов и сохранением независимых
фактов прежних наблюдений.

## «К тому же месту»

Отдельная проверка двух настоящих выдержек:

1. «В два часа тридцать минут отправились вверх.»
2. «До трех часов отправились вверх к тому же месту.»

Первая создаёт относительное место назначения с `coordinates_status=UNKNOWN`.
Вторая выбирает **тот же target_ref** через активный workspace Ignition.
Новый M вместо выбранного места не возникает. После исправления сравнения
квитанции оба наблюдения коммитятся; повтор не вызывает новых проб и тиков.
Отзыв исходного якоря инвалидирует зависимую ссылку и поддержанные ею факты;
recovery сохраняет это состояние. Изменённое ограничение ссылки отвергается.

Отдельно те же две выдержки соединены в один вход для проверки локальной
ветки: выбран тот же M через предшествующий SPATIAL_ANCHOR без обращения
к чужому CONTEXT_READ. Прямой прогон и воспроизведение сохранённых ответов
завершились EXECUTED; replay не меняет ledger и не вызывает новых проб/тиков.
Это композиционная проверка, а не утверждение, что фразы соседствовали
в исходном дневнике.

Это не непрерывное чтение всех дней: в prior-журнале полного прогона 28 июля
нет нужного раннего «вверх». Поэтому там остаётся типизированный неизвестный
референт и `NOMINAL_REFERENCE_UNRESOLVED`, а не выдуманное тождество с лесом.
