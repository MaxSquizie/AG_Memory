# Раннее сужение именных зависимостей

Дополнение V7 §4.7 к QUESTION_TREE_V1. Ресурсный opt-in:
`ProposalPolicy.composition.dependency_reduction=CONSTRAINT_TREE_V1`.
Новый путь включается при голом родительном варианте, выпущенном маркере
приложения. Более трёх именных кандидатов также переводят назначение ролей
в этот же редуктор; число слов не является грамматическим запретом. GENITIVE/
APPOSITION/CASE_DEPENDENCY доступны только при наличии их выпущенных лицензий.

## Порядок разбора

До декартова произведения ролей строятся локальные домены для каждой именной
головы. ROOT — допустимая роль основного предиката по целому морфологическому
варианту и валентности; DEFER_PP — последующий вопрос о хозяине предложной
группы; GENITIVE — зависимость родительного варианта от другой именной головы;
APPOSITION — именительный вариант после выпущенного пунктуационного маркера,
с хозяином перед этим маркером. Ближайшее слово не назначается хозяином
автоматически. Имена и отдельные фразы в алгоритм не входят.

Домены хранятся в общем `composition_domains.DomainNetwork`. Грамматический
поставщик `dependency_constraints` связывает варианты согласованием, запретом
двойного занятия роли и типом хозяина: отвергнутое NOUN-чтение нельзя использовать
как голову после выбора ADJF. Очередь дуг распространяет сокращения на соседей
без произведения целых разборов.

Следующим обрабатывается минимальный оставшийся домен, при равенстве — порядок
источника. Единственный вариант фиксируется программно; при нескольких
допустимых вариантах задаётся короткая закрытая проба. Зафиксированная ROOT-связь
занимает соответствующую единственную роль; новые зависимости не могут замкнуть
цикл через уже выбранные связи. Фиксированные связи и ID локальных альтернатив
сохраняются в трассе, исходные токены не удаляются.

Вопрос получает уже выбранные зависимости и исходную область. Если содержащий
её абзац целиком помещается в выпущенный `context_chars`, он также доступен как
исходный текст для интерпретации. Это не новая истинностная опора. Область
контекста входит в ключ вопроса; число кандидатов ограничено `max_candidates`.
Неоднозначный ответ откладывает слот: независимые ограничения продолжают
обрабатываться, возврат происходит только после изменения домена/фиксированных
связей. Если прогресса нет, сохраняется DEPENDENCY_RESIDUAL. Противоречие и
превышение бюджета оставляют разбор незавершённым. Выбор первого совместимого варианта запрещён. Жадное принятие
сомнительной связи ради успешного коммита не допускается; текущий конструктор
не заявляет полный поиск с возвратами.

После сужения только ROOT-участники входят в основную рамку. Именные зависимости
сохраняются как обязательства материализации: потреблённый токен не означает
готовый факт. Прежние PP-вопросы видят и эти головы. Совместное дерево
GENITIVE/APPOSITION/PP проверяется на циклы и достижимость основной рамки.
Если дерево не достроено, фрагмент остаётся `structural_unresolved`.

## Значение и запись

`dependency_senses` задаёт различные выпущенные senses GENITIVE и APPOSITION;
для каждого обязательны R-S, бинарная ENTITY STATE-валентность R-V и TemplateMap.
Роли хозяина и зависимого берутся из `nominal_host_role` и
`preposition_nominal_role`. T5 проверяет реальные T текущей AH.
`apposition_markers` содержит пунктуацию, а не списки фамилий или профессий.

GENITIVE обозначает грамматическую зависимость. Она сама по себе не означает
владение, авторство или принадлежность. APPOSITION сохраняет пояснение, но не
сливает две сущности. Эти описания материализуются как S-only N через прежние
NOMINAL UsageLinks; самостоятельной ROOT-опоры у них нет. Лицензия проверяет
морфологический вариант, роли и для приложения реальный маркер между головами.
T4/T5/T6, атомарность, отзыв источника и replay остаются обязательными.
Грамматический sense не записывается в R-X3 как лексическое значение слова,
служившего якорем: родительная связь не становится значением фамилии или имени.

## Границы

Относительное время получает типизированного EVENT_DESCRIPTION ребёнка через
общий compose_area; определения и именные зависимости обрабатываются там же.
Временная связь не создаёт отдельной опоры на якорное событие. Все способы
выражения якоря и координация именных групп не считаются автоматически покрытыми;
описания не теряются ради коммита. Ограничения текущего приложения: nominative
и выпущенный маркер; приложение к количественной группе в косвенной форме
пока не покрыто. Квалифицированные запросы по-прежнему требуют
поддержки query compiler, иначе `QUERY_NOMINAL_SCOPE_UNSUPPORTED`.

Диагностический release создаёт реальные T только в изолированной AH и остаётся
TEST_ONLY. Ответы изолированного исполнителя коротких проб не являются проверкой
локальной модели или доказательством высокого языкового покрытия.

## Внешнее чтение и чтение головы

Количественная группа отдаёт внешнюю роль и сохраняет исходное внутреннее
чтение головы. APPOSITION/ATTRIBUTE адресуют нужный слой через общий интерфейс
`nominal_readings`; их совместимость с выбранным хозяином проверяет
`dependency_constraints`. Ресурсное поле `apposition_rules` задаёт лицензии
NOMINATIVE/AGREEMENT с маркерами. Предложение и проверка лицензии принадлежат
`nominal_apposition`. Отдельного алгоритма для «количество + приложение» нет.
Номинативная legacy-лицензия сохраняется для release без нового поля.
Морфология контекстуального субстантива подтверждается исходным ADJF и
разрешённой пробой NOMINAL; она не теряется на границе материализации.
