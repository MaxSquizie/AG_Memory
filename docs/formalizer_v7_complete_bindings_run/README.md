Точные ID, ожидаемые и наблюдённые значения: [issues.json](issues.json). Данные архитектуры и gold не изменены ради результата. Исправления корпуса требуют отдельного review; этот снимок не объявляет все проверки пройденными.

Дополнительно прошли **185 профильных pytest-проверок**, включая настоящую HTTP-границу, native T0–T6, AH/WAL, CLI и offline replay. HTTP-сервер в этой проверке возвращал независимо заданные ответы: это проверка транспорта и механик, а не качества языковой модели. Replay после остановки сервера повторяет исходную выборку и не вызывает транспорт.

Исторический `test_formalizer_native_production.py` содержит четыре ожидания native-коммита/legacy-маршрута без обязательного release; отдельный диагностический прогон их не прошёл. Это не основание включать demo fallback. Привязанный runner использует валидируемые подписанные TEST_ONLY fixtures; результат 185 выше относится к перечисленным актуальным проверкам, а не ко всему pytest проекта.

`comparison.json`, `runtime_coverage.json`, `bindings.json`, `summary.json` и `actual.jsonl.gz` содержат сравнения, покрытие и фактические checkpoints. `provenance.json` фиксирует хеши исходников, корпуса и архивов. Для проверки архива сравните SHA256 gzip и SHA256 распакованных JSONL с provenance.

Полные файловые WAL и resource fixtures остаются в каталоге выполнения runner; компактный опубликованный снимок их не включает. Для повторения создайте новый каталог. Последующий replay использует полный каталог исходного прогона, а не этот компактный снимок.
