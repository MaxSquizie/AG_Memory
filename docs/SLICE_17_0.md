# Срез v0.17.0 — семантическое время, интервалы состояний и переходы

## Назначение

Версия 0.17.0 закрывает каноническую и исполняемую границу времени/состояний из архитектуры v4. Время не становится новым типом АГ-памяти: нормализованное семантическое время материализуется как обычный `m`, а факт `N` ссылается на него через роль `TIME`.

Целевой путь:

```text
TIME actant в CandidateIR
→ deterministic TemporalNormalizer
→ resolved TemporalCandidate | unresolved runtime reference
→ ordinary m_TIME
→ N.TIME -> m_TIME
→ TemporalReasoner / StateTracker
```

Runtime-типы `TemporalValue`, `TemporalCandidate`, `TemporalMode` и `TransitionOperator` не имеют UID, excitation или собственной persistence-сущности.

## 1. Представление времени

Канонический временной объект — обычный `m` со свойствами:

```text
kind = POINT | INTERVAL
start
end
precision
timezone
temporal_key
```

`temporal_key` используется только для детерминированной дедупликации одинаковых временных объектов. Отдельный canonical `q=TIME` не вводится.

Частичная дата не дополняется отсутствующими компонентами:

```text
2026          # известен только год
2026-09       # известны год и месяц
--09          # сентябрь, год неизвестен
T12:30        # время суток, дата неизвестна
2026-09-05    # день
```

Следовательно, `сентябрь` не превращается в сентябрь текущего года, а `12:30` не получает сегодняшнюю дату.

## 2. Техническое время и семантическое TIME разделены

`source_timestamp` и timestamp пережитого события используются как runtime/provenance anchors. Они **не** копируются в роль `TIME` каждого воспринимаемого факта.

Семантический TIME появляется только если временной актант реально присутствует в формализованном содержании либо уже передан parser-ом как нормализованный temporal candidate.

Это сохраняет границу:

```text
ingestion timestamp != semantic TIME fact
```

## 3. Относительное время

`TemporalAnchorContext` применяет приоритет архитектуры v4:

1. явный discourse/text anchor;
2. timestamp источника/документа;
3. timestamp текущего H-experience;
4. unresolved.

Детерминированно поддержаны простые формы, для которых значение однозначно при известном anchor: `сегодня`, `вчера`, `завтра`, `сейчас`, а также эти дни с явным временем суток.

Если относительное выражение требует anchor, но anchor отсутствует, создаётся runtime `UnresolvedTemporalRef`; canonical commit блокируется до разрешения. Система не подставляет системное время скрытым fallback.

Сложные ЕЯ-выражения вроде `прошлой неделе`, если их границы нельзя восстановить без семантического решения, остаются unresolved/обычным semantic candidate. 0.17.0 не заявляет универсальный natural-language temporal parser.

## 4. Детерминированные временные отношения

`TemporalReasoner` сравнивает только те точки/интервалы, порядок которых можно определить без заполнения отсутствующих компонентов.

Поддержаны отношения:

- `BEFORE`;
- `AFTER`;
- `OVERLAP`;
- `CONTAINS`.

Если отношение доказуемо, оно при materialization записывается как **обычный `N`**, а не как новый структурный `L.ID`. У результата сохраняется `ProofSupport` с `rule_id=TEMPORAL_INTERVAL_COMPARISON` и ссылками на оба временных объекта.

Неупорядочиваемые частичные значения дают `UNKNOWN`, а не `FALSE`.

`InferenceSchemaRegistry` явно знает логические свойства этих отношений; неизвестные отношения по-прежнему не получают свойства по имени.

`FOLLOW` не используется как физическое время и не превращается в `BEFORE` автоматически.

## 5. TemporalMode относится к occurrence, а не к T

У `AssertionCandidate` может быть runtime-классификация:

```text
STATE
EVENT
PROCESS
TRANSITION
```

После канонической интеграции выбранный режим сохраняется в metadata конкретного `N`. Шаблон `T` не получает глобальное свойство `STATE/EVENT/...`; один и тот же predicate может иметь разные временные чтения в разных употреблениях.

Классификация не угадывается `StateTracker`: он исполняет transition semantics только после того, как formalization уже передала `TemporalMode.TRANSITION` и конкретный оператор.

## 6. START / STOP / CONTINUE / AGAIN / NO_LONGER

В общем `FunctionRegistry` зарегистрированы канонические `g.ID`:

```text
START(P)
STOP(P)
CONTINUE(P)
AGAIN(P)
NO_LONGER(P)
```

Операнд обязан быть proposition reference `N/G`. Само изменение state intervals выполняет детерминированный `StateTracker` в той же atomic AH transaction, в которой интегрируется входной batch.

### START(P)

- не допускает уже открытый положительный `P`;
- если ранее явно существовал открытый `NOT(P)`, закрывает его в момент START;
- создаёт открытый положительный интервал `[t_start, ?]`.

### STOP(P)

- требует существующий открытый положительный `P`;
- закрывает положительный интервал в момент перехода; конец интервала трактуется как исключительная граница `[start, end)`;
- открывает `NOT(P)` с `[t_stop, ?]`.

### CONTINUE(P)

- требует именно открытый положительный `P`;
- открытый `NOT(P)` не может ошибочно удовлетворить `CONTINUE(P)`;
- не создаёт новый период состояния.

### AGAIN(P)

- требует ранее завершённый положительный период `P`;
- не допускает уже открытый положительный `P`;
- если существует явно сохранённый открытый отрицательный период, закрывает его;
- открывает новый положительный период;
- если отрицательного периода в памяти не было, `AGAIN` **не изобретает промежуточный `NOT(P)`**.

### NO_LONGER(P)

Исполняется как переход от существующего открытого `P` к открытому `NOT(P)`, сохраняя отдельный канонический wrapper `g_NO_LONGER`.

Переход, пытающийся закрыть интервал раньше его начала, отклоняется; поскольку обработка идёт внутри `AHCore.transaction()`, batch откатывается целиком.

## 7. Текущее состояние определяется покрытием времени

`StateTracker.current_truth(P, t)` возвращает:

```text
POSITIVE
NEGATIVE
UNKNOWN
CONFLICTED
```

Результат вычисляется по интервалам, покрывающим `t`, а не по последнему textual mention и не по creation sequence. Для точной границы STOP состояние `P` уже не покрывает сам момент STOP; при грубой календарной точности пересечение с неопределённой границей не выдумывается и остаётся `UNKNOWN`.

Отрицательный state operand учитывается как отрицание только если он действительно принадлежит canonical `NOT(...)`; scoped `N` сам по себе не превращается в отрицательный факт.

Если одновременно покрываются допустимые `P` и `NOT(P)`, результат `CONFLICTED`, а не автоматический выбор более нового/активного значения.

## 8. Proof support и persistence

Производные state/negation structures получают `SupportRecord` с оператором перехода и каноническими premise refs. Временные `m`, transition wrappers `g`, state intervals и proof supports сохраняются обычным `JsonPersistence` и после reload восстанавливают ту же temporal/state semantics.

Runtime normalizer, anchor context и staging references не становятся отдельной памятью и не сериализуются как canonical nodes.

## 9. Сохранённые инварианты

- `AH=<S,C,P,H,L>` не расширен новым canonical типом.
- `TIME` — роль `N` на обычный `m`, не новый `q`.
- `IS-A`, `FOLLOW`, `CAUSE` не изменены.
- `CAUSE` не становится транзитивным.
- `FOLLOW != physical time`.
- `activation != truth`, `w != confidence`.
- частичное время не дополняется предположениями;
- отсутствие события не доказывает `NEVER(P)`;
- `TemporalMode` не является глобальным свойством `T`;
- переходы исполняются детерминированно после formalization, а не по keyword-trigger внутри state engine;
- unresolved relative time блокирует запись вместо forced guess;
- temporal derived relation materialize как `N` с support, а не как произвольно изобретённый `L`.

## 10. Что сознательно не заявляется готовым

0.17.0 закрывает canonical/runtime/integration semantics времени и состояний, но не универсальную семантику всех временных фраз естественного языка.

Не заявляются:

- общий разбор произвольных календарных выражений и сложных анафор времени;
- автоматическое извлечение всех discourse anchors из свободного текста — parser/consolidator может передать уже разрешённый explicit anchor;
- `NEVER(P)` как отдельный shortcut: по v4 это кванторная временная формула, а отсутствие известных эпизодов не является доказательством;
- полноценный интервальный constraint solver;
- превращение `FOLLOW` в временную шкалу.

Эти ограничения fail closed и не создают ложных temporal facts.
