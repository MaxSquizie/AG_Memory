# Активный V7: ответы модели без JSON

В `RealBackendSelector` по умолчанию включены два явных транспортных протокола:
`TP-C2` для ограниченной структурной гипотезы и `SELECT_LABELS_V1` для выбора.
Модель не сериализует `Hypothesis`, `SelectionResponse`, MutationPlan или граф AH.
Python строит типизированные объекты и применяет прежние проверки.

Это изменение активного V7 runtime и оракульного runner. Изолированные старые
probe helpers не вызываются из V7/bootstrap/GUI и не являются его новым каналом.
Нормативные ворота архитектуры этим изменением не переоцениваются.

## Выбор из закрытого множества

Код задаёт стабильные номера уже построенных кандидатов. Ответ занимает одну строку:

| Ответ | Типизированный исход |
|---|---|
| `2` | ONE_SELECTED: кандидат с номером 2 |
| `1,3` | MULTIPLE_ADMISSIBLE: оба кандидата |
| `?` | INSUFFICIENT_CONTEXT |
| `0` | NONE_FIT |

Номера преобразуются в реальные candidate IDs по таблице из записанного запроса.
Результат проходит существующий валидатор закрытого множества и кардинальности.
JSON, объяснения, неизвестные/повторные номера и смешанные ответы отклоняются.
Новый протокол подключён к выбору TP-гипотез, лексических значений и референтов.

## Структурный пробел

Когда декларативные правила не закрыли структуру, TP ещё требуется для предложения
локальных связей и областей действия. Модель возвращает короткие читаемые записи:

```text
H h0 t0,t1
N n0 PREDICATE t1
N n1 ENTITY t0
E ARGUMENT n0 n1 role=SUBJECT
END
```

Это иллюстрация формата: типы узлов, рёбер и роли разрешает каталог запроса.
Ссылки `t*` обозначают токены, `n*` — явно объявленные узлы, `f*` — захваченные
морфологические варианты. Код раскрывает их в исходные anchors и Hypothesis.
`head=t1` задаёт лексическую голову, `features=f0,f1` — выбранные морфологические
варианты, `scope` — scope=true. Порядок операндов и отдельные альтернативы сохраняются.
Одна строка `ABSTAIN` означает отказ предложить структуру. Модель не создаёт memory IDs,
canonical T/Ref, JSON-поля или truth grounds.

В TP-C2 нет перенесённых инструкций о JSON-полях. Пример в запросе объясняет
только синтаксис записи, без русских слов или ответов oracle. Неизвестное слово
не требует отказа, если локальная структура подтверждена; семантическое покрытие
определяется последующими стадиями. Структура NOT/цитаты/вопроса не требует
утверждения истинности её содержимого.

После раскрытия выполняется тот же `validate_structure_reply`: проверяются типы,
якоря, головы, роли, scope, замыкание, циклы и бюджеты. Валентности, эпистемика,
семантическое разрешение и admission остаются последующими границами V7.
JSON во входном запросе и внутренних артефактах формирует код.

## Детерминированное выполнение

У прежней языковой фикстуры SyntaxRules были пусты, а `verify_deterministic=true`
принудительно требовал TP. Теперь TEST_ONLY release содержит 8 общих форм конечной
клаузы, скомпилированных из окончательных R-S/R-V и зарегистрированных ENTITY-ролей.
В SyntaxRules закреплены зависимости R-S/R-V. Это ресурсные данные тестового стенда;
production loader не подменяет отсутствующий reviewed release этой фикстурой.

Правило допускает обход TP только при полном покрытии предложения: каждый токен
захвачен структурой, кроме конечной пунктуации `. ! ?`. Сохраняются все подходящие
морфологические чтения и конкурирующие привязки. Scope, цитаты, предлоги, составные
упоминания, временные выражения и неконечные предикаты остаются в обычном TP-пути.
Частных правил по case ID, предложению или ожидаемому ответу нет.

Фикстура явно подписывает `max_rule_steps=100000`; фактический максимум на холодном
разборе 640 входов — 28050. Превышение объявленного бюджета остаётся отказом,
а не разрешением частичного кандидата. На этом наборе исчерпаний не было.

## Durable-контракт

ProviderAdapter сохраняет полученный текст до декодирования, вместе с request digest,
параметрами и ordinal. Оба протокола и system prompt входят в params hash; каталоги и номера — в
prompt digest. Replay возвращает исходные bytes без обращения к модели.
Смена формата при том же replay-ключе даёт REPLAY_MISMATCH.

Исходное соответствие токенов и морфологических вариантов закреплено отдельным
`reference_binding_sha256` в запросе. Короткие ссылки не стирают идентичность
захваченных исходных записей. Входной JSON и последующий напоминатель формата
сериализует код.

`JSON_V1` сохранён как отдельный явно выбираемый контракт для authored legacy
фикстур. TP-C1 сохранён неизменным для явно закреплённых старых запусков вместе
с прежним system prompt. Декодер не угадывает формат, не исправляет заголовки
или индексы и не пробует JSON после отказа TP-C2.
Новый live-прогон требует новый каталог артефактов. CLI сохраняет названия обоих
протоколов в `run_config.json`.

## Регрессия TP-C1 на локальной модели

Свежий частичный прогон `gui_20261010_214525_1c813458` завершил 78 кейсов:
**12 PASS / 66 FAIL**. На тех же case IDs предыдущий JSON-прогон имел
**73 PASS / 5 FAIL**: 61 прежний PASS стал FAIL. Все 68 завершённых HTTP-запросов
успешны, reasoning отсутствует. 40 ответов — отказ `-`, 26 не прошли протокол:
19 пропусков `H`, 4 неверных записи alternatives, 3 ошибки адресации узлов.
Десять PASS получены без модели, два — через валидный TP-C1.

Это регрессия модельного wire-контракта. В ответах смешиваются позиции токенов
и узлов; запрос также одновременно содержит инструкции индексов и старые
инструкции JSON. Конкретный мотив каждого отказа `-` неизвестен.
Поэтому новый дефолт TP-C2 разводит ссылки, использует читаемые имена и собственные
инструкции. Валидатор, gold, ресурсы, логика коммита и truth grounds не ослаблены.

Ускорение этого неудачного прогона не считается улучшением: большая часть
сокращения времени пришлась на короткие отказы. Надёжность **новой генерации
TP-C2 пока не измерена**: требуется свежая небольшая проба локальной модели
перед повтором всех 640 кейсов.

## Проверка TP-C2 без модели

На 592 записанных вызовах TP-C1 выполнен чистый контроль кодека:
577 валидных ответов раскрыты в Hypothesis, сериализованы в TP-C2 и снова
раскрыты — **все Hypothesis совпали точно**. Остальные 15 невалидных исходных
ответов остались отклонёнными; исправление не применялось. Текст токенов,
полные морфологические варианты и каталоги разрешённых значений сохранены.
Новых обращений к модели, обращения к gold или повторного исполнения runtime
в этом контроле не было.

| Размер в символах на одинаковых запросах | TP-C1 | TP-C2 |
|---|---:|---:|
| 592 входных запроса | 7040513 | 7645727 |
| 577 валидных ответов | 53447 | 105511 |

Читаемый TP-C2 длиннее непрозрачного TP-C1; относительно исходного JSON
тех же 577 ответов (754818 символов) он короче на 86,02%. Это размеры
кодовой сериализации, а не результаты генерации модели и не измерение её
скорости. Проверены новый кодек, строгий отказ, HTTP-коммит и replay;
результаты свежего live-прогона TP-C2 пока отсутствуют.

В offline-контроле старые ответы преобразовывались существующим кодеком, без чтения
gold как входа алгоритма. Это не генерация нового ответа моделью и не точный replay
старого запуска: ресурсная фикстура и wire-контракт изменились. Gold не изменялся.

48 исключённых старых HTTP-запросов занимали в предоставленном прогоне 303,35 с.
Этот offline-контроль доказал сохранность готовых Hypothesis, но не способность
модели воспроизвести новый формат; свежий live-прогон выше выявил его регрессию.
Сокращение символов не объявляется равным сокращению токенов или времени.
71 прежний FAIL этим изменением не исправлялся.

Объединённая проверка затронутых seams/кодеков/ресурсов дала 282 успешных теста;
отдельный актуальный HTTP/replay-файл — ещё 9. Семь ошибок старых тестов
`tp_proposer`, `provider_adapter`, `run_and_provider` воспроизводятся в неизменённом
родительском коммите `75c95b4` с теми же причинами (устаревшие alignment/ordinal/
binding ожидания). Они не устранены этим патчем; весь проект зелёным не объявляется.
