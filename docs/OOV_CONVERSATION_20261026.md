# Разговорный пример без запятых и с OOV

База: `c0da5782a4ed39c6a687fa80def2226cfa198521`. Исполнитель: отдельный `gpt-6-luna`, low, без истории проекта для каждого нового запроса. Ресурс native harness — TEST_ONLY; это не запуск Qt GUI или производственного словаря. Производственный код в этой диагностической работе не менялся.

Исходный текст:

> Я попросил Диму зафлюмить квендрик но он сказал что квендрик не работает и попросил меня подождать.

У предложения есть внешнее соединение просьбы и последующего сообщения/просьбы. Точное присоединение последней просьбы при такой пунктуации может потребовать отдельного выбора; оно не делает всё предложение одной лексической предикацией. Значение вымышленных слов заранее не задано. Повтор написания «квендрик» сам по себе не устанавливает тождество объектов.

## Фактический результат

Четыре вызова исполнителя: функция «зафлюмить» → `7` (инфинитив); функция «квендрик» → `1` (существительное); внешняя связь всего предложения → `1` (LEXICAL); граница инфинитивного содержания → `0` (ни один вариант). Ответы не заменялись сценарными ответами.

Native завершился с `RESOLUTION_ONLY`, `applied=false`, без фрагментов и утверждений; покрытие `NONE`, фреймов нет. Диагностика: `COMPONENT_INFINITIVE_UNRESOLVED`, `STRUCTURAL_IMPLEMENTATION_GAP`, `STRUCTURE_NOT_COVERED`, `OOV_KEEP_AS_IS`. Это не корректный PARTIAL-разбор. Состояние `SEALED` и `structural_closed=true` в этом запуске не означают семантической готовности.

## Причинная цепочка и нарушения контрактов

1. **Выбор функции OOV не адресован вхождению.** `contextual_oov.resolve` передаёт целый регион и вопрос только с написанием слова. В `structural_tasks._choose` ключ зависит от региона, области задачи, вариантов, вопроса и страницы, но здесь не содержит целевое вхождение. Для двух «квендрик» в трассе записаны разные `token_ref`, однако один `decision_ref`: `task-domain:8b7a799cb4691f49eaa1965ae20bcaadc00cb77dbaf62954ce2996d401b31b12`. Второго вызова исполнителя не было. В этом тексте оба употребления — существительные, поэтому перенос не изменил ожидаемый POS, но основание не доказывает функцию каждого вхождения. Общий дефект затрагивает повторяющиеся OOV с разными функциями.
2. **Первый неверный смысловой выбор — внешняя связь.** Ответ LEXICAL допускает переход к лексическому компоновщику для всего сложного предложения. Проба одновременно предъявляет двадцать типов, а в корневом запросе инструкция говорит о TARGET, хотя текст оформлен только как `Context span`. Это наблюдение о формулировке и единичный фактический неправильный ответ, не доказательство единственной причины ошибки модели.
3. **Домен границ уже неполон.** В `component_infinitives.compose` концы допускаются перед следующим морфологически распознанным VERB или в конце региона. Правильного первого содержания «зафлюмить квендрик» нет среди пяти предложений; ближайший вариант захватывает «но он». Такой перебор не обеспечивает полноту для синтаксических границ. Сбой внешней классификации лишь привёл исполнение в эту ветвь; ошибка домена самостоятельна. Пятый вариант относится к другому инфинитиву («подождать»), поэтому ответ `0` не следует трактовать как доказательство отсутствия любых допустимых инфинитивных связей в языке.
4. **Отклонённая страница превращается в вопрос пользователю.** `component_infinitives.compose` вызывает `_probe` с `offer_clarification=True` по умолчанию. `component_probe._live_probe` при любом ответе, отличном от ONE_SELECTED, предлагает все варианты. После NONE_FIT в `clarification_candidates` сохранились все пять границ. Здесь не применяется защита владельца полного домена из `structural_tasks.choose`. Пользовательский выбор из этого списка не исправляет отсутствующий правильный вариант.

Поздний отказ не вернул анализ к внешней связи или генератору границ. Запись остановлена, но причинного пересмотра и готовой частичной структуры нет.

## Что подтверждено для неизвестных слов

Все три вхождения действительно имеют `OOV_KEEP_AS_IS`; исходные `variants=[]`, `pos=null`, `cases=[]`. Прогнозы pymorphy, включая ложное имя «зафлюмитя», остались в `morph_guesses` с `origin=PREDICTED`. Функциональные ограничения INFN/NOUN имеют отдельные основания. Этот запуск не превратил прогнозы в установленные морфологические факты. Дальнейшие роли, лексическая канонизация и тождество двух упоминаний не проверены: исполнение остановилось раньше.

## Изолированные контрасты внешней связи

Менялся только текст в том же окончательном вопросе. Эти три проверки не являются сквозными прогонами.

| Вход | Ответ Luna low |
| --- | --- |
| OOV, добавлены запятые | `?` |
| Без запятых, «починить принтер» вместо OOV | `1` — LEXICAL |
| С запятыми, «починить принтер» | `0` |

Ни один ответ не установил внешнее соединение. Одного запуска каждого варианта недостаточно для статистики надёжности или вывода о превосходстве одной формулировки. Однако эти наблюдения не поддерживают объяснение сбоя исключительно отсутствием запятых или неизвестной лексикой.

Первые попытки доставить контрастные вопросы через пути к файлам дали неподтверждённое чтение/посторонние ответы. Они отдельно сохранены как невалидные попытки доставки. Итоговые контрасты предъявлялись новым изолированным агентам целиком в сообщении без подсказок. Исходные четыре агента подтвердили чтение файлов через инструмент; четвёртый также сам записал ответ в mailbox.

## Следующая работа

Сначала адресовать выбор функции конкретному вхождению и не выдавать NONE_FIT за основание пользовательского выбора. Затем согласовать внешнюю структурную пробу с её потребителем: явная цель, понятные различия, проверяемое обязательство для перехода к лексическому разбору и причинный пересмотр при нарушении обязательства. Границы должны выбираться из полного заявленного домена, а не из эвристического набора позиций перед глаголами. Добавление слова «но» в список разделителей не решает эту проблему.

Точные семь запросов и ответов: `evidence/oov_conversation_luna_20261026.jsonl`. Сокращённый снимок исходных OOV, решений, границ, уточнений и native-результата: `evidence/oov_conversation_trace_20261026.json`.

Воспроизведение native-прогона с фактическими ответами возможно через `tools/recovery/run_live_example.py`: mailbox сопоставляет точные system/prompt по SHA-256. Повтор с сохранёнными ответами будет воспроизведением протокола, а не новым живым испытанием.
