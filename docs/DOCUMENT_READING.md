# Разбор произвольного файла через V7

В GUI откройте панель «Документ → AH», выберите TXT/Markdown/DOCX и нажмите
«Разобрать файл в AH». Используются настроенный провайдер, текущая память,
проверенный релиз ресурсов и `structure_mode="region_probes"`. Модель отвечает
на короткие пробы; модельный построитель графов не включается как fallback.

CLI из установленного окружения проекта:

```bash
python -m ah.documents --config config/lmstudio.toml read book.txt --out data/document_runs/book_01 --save
```

Каталог `--out` должен быть новым. При необходимости передайте явный
`--time-anchor 2026-10-10T00:00:00+03:00`. Дата изменения файла не становится
датой событий книги. Настройка модели и релиза берётся из TOML; учебные ресурсы
из оракла не подставляются. В GUI путь к результатам показывается после запуска.
Личность загрузившего файл пользователя, часы диалога и его местоположение
также не становятся личностью рассказчика, временем или местом повествования.
CLI `read` сохраняет исходник и `STOPPED`-отчёт даже при ошибке загрузки ресурсов.

Артефакты:

- `source.<расширение>` — исходные байты; `source.txt.decoded` — декодированный текст.
- `progress.jsonl` — этапы, реальное число вызовов/повторов модели, чтение токенов и время.
- `regions.json` — дерево предварительных областей, кандидаты и поперечные ограничения.
- `interpretation.json` — фактический IR, решения, grounds, контекстные чтения, receipt коммита.
- `report.json` — исход, диагностические пробелы, исходные диапазоны и затраты по этапам.

При ошибке до получения IR файлы `regions.json`/`interpretation.json` не создаются.
`STOPPED` не означает отката уже состоявшихся durable-коммитов: проверяйте receipt.
`EXECUTED` означает, что проход завершился, а не что весь текст правильно понят.
`semantic_correctness=NOT_EVALUATED` сохраняется: произвольный файл не содержит
эталонного ответа. Непривязанные к фреймам токены включают пунктуацию и не служат
метрикой смыслового покрытия.

Повтор того же источника на той же памяти использует штатный V7 replay, без
повторных тиков и опор. Изменённый файл получает другую content identity.
Осознанную переинтерпретацию прежнего наблюдения следует выполнять через
declared trigger, а не редактированием отчёта.

## Текущая граница реализации

Native-файл поступает одной observation с точными исходными координатами.
Раньше размерные chunks становились самостоятельными высказываниями и могли
разорвать цитату. Теперь кавычки/скобки защищаются также при поиске синтаксических
окон; предварительное разбиение дерева не выдаёт разрешение на отдельный коммит.
Ignition сохраняет событийный порядок чтения, а завершение H-карриера не возбуждает
всю книгу заново.

Это рабочий способ исследовать фактические пробелы на своём тексте. **Потоковый
композиционный разбор книги пока не завершён:** сложное окно SyntaxRules может
исчерпать свой бюджет; frontier безопасных частичных коммитов и разрешение
далёких ссылок через ещё не закоммиченные кандидаты требуют продолжения работы.
Бюджетный отказ сохраняется явно, без увеличения лимитов для сокрытия пробела и
без частных правил под предложения файла.

В новых DOCUMENT-запусках `region_probes` `syntax_budget_scope=SOURCE_WINDOW_V1`
закрепляется в durable input. `max_rule_steps`/`max_rule_matches` относятся к
одному исходному окну суммарно по всем правилам, а не к книге целиком или каждому
правилу отдельно. Общая работа ограничена числом различных окон и их бюджетами.
Исчерпание одного окна по-прежнему блокирует незавершённый общий поиск; успешный
префикс не объявляется полным разбором. Отчёт показывает диапазон проблемного окна.
Старый run без этого поля сохраняет прежний scope бюджета при replay.

До декартова перебора выполняется консервативная проверка областей возможных
значений AST: отвергается лишь комбинация, для которой `True` невозможно.
Неизвестность сохраняется; морфологические варианты по вероятности не обрезаются.
`FEATURE_CHECK_BATCH` хранит все проверки в `checks[]` с явными `columns[]`:
step/token_ref/variant_index/result. Это упаковка повторяющихся полей, не выборка
трассы. Запись JSON потоковая; `pipeline_seconds` и `artifact_seconds` разделены.

## Короткие пробы через внешнего исполнителя

Для изолированного диагностического запуска без локальной модели:

```bash
PYTHONPATH=src:. python -m tools.read_document_probe_mailbox book.txt --out data/document_runs/probe_01 --development-fixture
```

Это явно **TEST_ONLY**: прежний общий лексический fixture, настоящая морфология,
новая AH, обычные T0–T6/ProviderAdapter, без gold-кейсов и oracle entity bindings.
Production-запуск выше по-прежнему требует настоящего reviewed release.
На каждый реальный запрос инструмент сохраняет `probe_NNNN.request.json` и ждёт
`probe_NNNN.reply.txt`. Передавайте изолированному исполнителю только точные
system/prompt этой записи. Ответ записывайте атомарным переименованием временного
файла; его формат проверяет штатный ProviderAdapter. Другие файлы, код и желаемый
результат исполнитель не видит. Наличие `CANCEL` отменяет ожидание, отсутствие
ответа за 900 секунд даёт транспортный отказ. Это не замер локальной модели:
в elapsed входит ожидание внешнего исполнителя. Если T2 не создал кандидатов,
запроса может вообще не возникнуть — инструмент его не выдумывает.

Для повторной диагностики добавьте `--captured-probes <каталог request/reply>`.
Ответ используется только при точном совпадении всего запроса; новый запрос
останавливается с `CAPTURED_PROBE_MISSING`, неодинаковые сохранённые ответы — с
`CAPTURED_PROBE_AMBIGUOUS`. В артефактах явно отмечается
`EXACT_CAPTURED_TRANSPORT`: это не новая проба модели и не native replay run_id.
Пример фактического прохода и ограничения: [DIARY_FORMALIZATION_RUN.md](DIARY_FORMALIZATION_RUN.md).

Для первого контура неявных субъектов и групп добавьте `--components`.
Он включает `COMPONENTS_V1` через новый явно TEST_ONLY resource release/hash;
production требует собственной reviewed-политики `ProposalPolicy.composition`.
Подробности, границы покрытия и проверка исходного дневника:
[COMPONENT_ARGUMENTS_RUN.md](COMPONENT_ARGUMENTS_RUN.md).
