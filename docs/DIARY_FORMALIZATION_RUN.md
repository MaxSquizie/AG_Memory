## Как использована модель

Четыре настоящих коротких запроса исполнены четырьмя изолированными субагентами.
Каждый получил только точные system/prompt штатного ProviderAdapter и ответил
одной меткой `0` — NONE_FIT. Модель не создавала подграфы и не видела желаемый
результат, исходники или остальные части дневника.

В запросах «Весь вечер читал» варианты ошибочно назначали «Весь» и «вечер»
субъектом/объектом в обоих порядках. Правильного кандидата с обстоятельством
времени и невыраженным субъектом в замкнутом наборе не было. Отказ модели здесь
корректен; подставлять ответ или добавлять правило под эту фразу нельзя.

Последующие сравнения runtime используют записанные ответы только при точном
совпадении всего запроса, включая system/kwargs. Это воспроизведение транспорта
в новом изолированном запуске, не native replay прежнего run_id и не замер
скорости локальной модели. Несовпавший запрос даёт CAPTURED_PROBE_MISSING;
различные записанные ответы на один запрос — CAPTURED_PROBE_AMBIGUOUS.

## Воспроизведение

```bash
PYTHONPATH=src:. python -m tools.read_document_probe_mailbox book.txt --out data/document_runs/diary_new --development-fixture
```

Исполнитель получает `probe_NNNN.request.json`, возвращает только разрешённую
метку в `probe_NNNN.reply.txt` атомарным переименованием. Для диагностического
повтора доступен `--captured-probes <каталог сохранённых request/reply>`.
Не используйте прежний output-каталог: инструмент требует новый, чтобы не
перепутать ответы или состояния независимых запусков.

Точные timings, receipt, hashes и короткие пробы сохраняются в сопровождающем
архиве. Неуспешные исследовательские запуски отдельно помечены; RUNNING после
прерывания процесса не считается завершённым результатом.

G0 и остальные ворота этим экспериментом не пересматриваются. Полнота и
семантическая правильность всего документа имеют статус NOT_EVALUATED.
