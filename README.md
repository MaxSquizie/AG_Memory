# AG Memory

**Ассоциативно-гетерархическая долговременная память для языковых агентов.**

AG Memory преобразует естественный язык в типизированные структуры, связывает их с канонической памятью, хранит основания утверждений и предоставляет агенту релевантный фрагмент памяти. Формализатор V7 определяет правила интерпретации и записи; ассоциативная активация и символический вывод работают с уже сохранёнными структурами.

Ниже показано прохождение **одного предложения по всему контуру**. Промежуточные результаты — **иллюстрация допустимых кандидатов**, а не протокол реального запуска. Полный результат зависит от контекста, версий ресурсов и подтверждённых правил.

## Исходное предложение

> Привет, Я - твой ИИ ассистент Крипл!

В нём различаются две части:

- **«Привет»** — слово с возможной функцией приветствия. Самостоятельный канонический механизм приветствия здесь не предполагается.
- **«Я — твой ИИ ассистент Крипл»** — именная конструкция без выраженного глагола-связки. Её интерпретация зависит от синтаксических и семантических ресурсов.

Для разрешения **«я»** и **«твой»** нужен объявленный контекст: сведения о говорящем (`self_ref`) и адресате (`user_ref`). Если эти ссылки не заданы, формализатор не вправе самостоятельно приписать фразу конкретным участникам.

## Разбор предложения

### 01. T0 — исходная строка

**Вход:** текст сообщения, его источник, ревизия, вид обращения и снимок ресурсов.

**Действие:** фиксация всех символов, токенов, пробелов и знаков препинания. Сохраняются исходные диапазоны.

**На примере:** `Привет`, `Я`, `-`, `твой`, `ИИ`, `ассистент`, `Крипл`, `!` сохраняют связь с исходной строкой. Не изменяются регистр, пунктуация и написание имени.

**Результат:** токены и единица исходного предложения. Семантических фактов пока нет.

### 02. SRL — первичные варианты разбора

**Вход:** токены, морфологические гипотезы и синтаксические правила.

**Действие:** построение возможных лексических интерпретаций, границ и частей конструкции. Для каждой формы сохраняется вариант `KEEP_AS_IS`.

**На примере:** выделяются начальное `Привет` и возможная именная конструкция после запятой. Неизвестное `Крипл` остаётся исходной формой; исправление слова без основания запрещено.

**Результат:** варианты границ и структуры, ещё без утверждения их правильности.

### 03. T1 — морфология и упоминания

**Вход:** варианты SRL и морфологический ресурс.

**Действие:** определение возможных лемм, частей речи, грамматических признаков и групп слов.

| Фрагмент | Возможный разбор |
|---|---|
| `Я` | местоимение, первое лицо, именительный падеж |
| `твой` | притяжательное местоимение, согласуется с именной группой |
| `ИИ` | сокращение; лексическое значение зависит от ресурса |
| `ассистент` | существительное, именительный падеж |
| `Крипл` | имя-кандидат; исходное написание сохраняется |

**Результат:** кандидаты упоминаний. Неизвестная лексема не считается опечаткой.

### 04. TD — зависимости и ссылки

**Вход:** упоминания T1, правила связей и объявленный контекст.

**Действие:** определение синтаксической зависимости между словами и кандидатов референции.

**На примере:** `твой` связывается с именной группой, `я` рассматривается как кандидат на обозначение говорящего. Если заданы `self_ref` и `user_ref`, проверяется их привязка к местоимениям. При отсутствии нужного контекста связь остаётся неопределённой.

**Результат:** кандидаты зависимостей и ссылок. Окончательные идентичности ещё не присвоены.

### 05. T2 — предикативная рамка

**Вход:** зависимости TD и ресурс валентностей.

**Действие:** сборка предикативной структуры с допустимыми ролями и ограничениями. V7 предусматривает обработку **именных конструкций без явного глагола**.

**На примере:** возможна рамка для содержания `я — ассистент`. Отношение к `Крипл` (имя, приложение либо другая допустимая структура) нельзя назначать по одному соседству слов. Оно должно быть подтверждено объявленными правилами.

**Результат:** одна или несколько рамок с ролями, границами и непокрытыми позициями.

### 06. TP — локальная структурная гипотеза

**Условие:** необходимые связи не построены правилами на предыдущих стадиях.

**Действие:** допускается ограниченная гипотеза LLM-парсера, проверяемая по типам, исходным диапазонам, разрешённому контексту и ограничениям.

**На примере:** TP может предложить структуру именной предикации, если не удалось восстановить её детерминированно. Он не вправе назначить каноническую личность Крипл или произвольное отношение имени.

**Результат:** проверенная локальная гипотеза либо явный структурный пробел.

### 07. structural_seal — фиксация структуры

**Действие:** фиксируется версия структурного графа: границы, рамки, зависимости, ссылки и области действия.

**На примере:** дальнейшие стадии могут выбирать смысл конструкции `я — твой ИИ ассистент Крипл`, но не добавлять к ней новые структурные рёбра.

**Результат:** неизменяемая структура текущей интерпретации.

## Разрешение смысла

### 08. T3 — значения предикатов

**Вход:** зафиксированная структура и версионированные семантические ресурсы.

**Действие:** проверка допустимых значений: схема предиката, словарь смыслов, сохранённые кандидаты, объявленные контекстные знания и, при подходящих условиях, открытая лексическая запись.

**На примере:** определяется, допускают ли ресурсы конкретное отношение между говорящим и ролью ассистента, а также обоснованную интерпретацию `Крипл`. При неизвестном значении возможен `OPEN_LEXICAL`, но он не устанавливает синонимию или тождество с уже известным смыслом.

**Результат:** кандидаты значений с указанием источников и ограничений вывода.

### 09. T4 — согласование решений

**Вход:** значения T3 и ограничения предыдущих стадий.

**Действие:** проверка совместимости вариантов и полноты поиска.

**Возможные исходы:** `RESOLVED`, `AMBIGUOUS`, `INSUFFICIENT_CONTEXT`, `NO_CANDIDATE`, `UNRESOLVED`.

**На примере:** если есть однозначные роли и смысловая схема, возможно `RESOLVED`. Если неясно, что обозначает `Крипл`, или неизвестен говорящий, соответствующая связь не объявляется разрешённой.

**Результат:** выбранная допустимая интерпретация либо мотивированная неопределённость.

### 10. assemble_candidate_ir — итог формализации

**Действие:** все кандидаты, решения, исходные диапазоны, зависимости, основания и диагностические сведения собираются в неизменяемое `FormalizerCandidateIR`.

**Результат:** представление, готовое к канонической привязке. Записи в памяти ещё нет.

## Каноническая память

### 11. C — сопоставление с существующими знаниями

**Вход:** `FormalizerCandidateIR` и доступное для чтения состояние АГ-памяти.

**Действие:** определение канонических сущностей, шаблонов и уже существующих структур; построение плана записи.

**На примере:** возможная ссылка на говорящего сопоставляется с подтверждённым объектом памяти. Имя `Крипл` не используется само по себе как доказательство идентичности. Связь роли записывается в план только при допустимой семантической привязке.

**Результат:** план канонических изменений, без записи в память.

### 12. T5 — проверка и журнал

**Действие:** проверка завершённости решения, актуальности ресурсов, целостности связей и оснований утверждения. Допустимый пакет фиксируется в устойчивом журнале.

**На примере:** само высказывание может дать основание **тому, что говорящий утверждает определённое содержание**. Это не независимое подтверждение всех свойств, приписанных говорящему. Неоднозначные фрагменты не записываются как подтверждённые факты.

**Результат:** подготовленная запись либо отказ от материализации соответствующего фрагмента.

### 13. T6 — запись в АГ-память

**Действие:** атомарное применение допущенного плана: создание или повторное использование языковых символов, канонических сущностей, шаблонов, предикативных структур, связей и записей поддержки.

**На примере:** если интерпретация подтверждена, в памяти появляется структурное утверждение о роли говорящего с опорой на источник сообщения. Связь с именем `Крипл` добавляется только при разрешённом смысле и канонической привязке.

**Результат:** поддержанные узлы в АГ-памяти. Если необходимый ресурс или контекст отсутствует, полного канонического результата может не быть.

![Условная схема канонических связей после успешной интерпретации](docs/assets/cripl-associations.svg)

### 14. T6b — повторная интерпретация

**Условие:** изменился объявленный контекст, ресурс или исходное наблюдение.

**Действие:** создание новой версии интерпретации; отзыв устаревших опор и пересчёт зависимых сведений.

**На примере:** если позднее выяснилось, что говорящий был определён неверно, исправляется соответствующая привязка и её поддержка. Исходное сообщение и история изменений сохраняются.

## Вспоминание и вывод

После записи агент использует отдельный контур работы с памятью:

1. **Активация.** Входной стимул возбуждает связанные элементы графа.
2. **Рабочее пространство.** Отбирается актуальная часть памяти.
3. **Вспоминание.** Находятся релевантные сохранённые сведения.
4. **Символический вывод.** При необходимости проверяются логические следствия по действующим основаниям.
5. **Подготовка контекста.** Доступные сведения передаются агентской LLM, формирующей ответ.

Пример последующего вопроса: **«Как тебя зовут?»**

Если подтверждены адресат, говорящий и связь его имени, память может предоставить имя `Крипл` для ответа. При нерешённой привязке имени ответ не должен считаться доказанным.

**LLM-парсер** выполняет ограниченные задачи интерпретации внутри формализатора. **Агентская LLM** использует подготовленный контекст. Это разные архитектурные роли.

## Установка и встраивание

Требуются Python 3.12+, `uv` и подключение к языковой модели.

```bash
git clone --branch temp https://github.com/MaxSquizie/AG_Memory.git
cd AG_Memory
uv venv
uv pip install -e ".[gui]"
```

После настройки модели и необходимых ресурсов:

```bash
uv run ah-gui --config config/ollama.toml
```

Для формализатора V7 необходимы согласованные утверждённые ресурсы и канонические шаблоны памяти. Порядок их подготовки описан в [документации по запуску](docs/RUN.md).

Для встраивания используются подсистемы в `src/ah/`; программные точки подключения приведены в [карте реализации](docs/IMPLEMENTATION_MAP_V7.md).
