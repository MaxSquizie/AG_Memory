# AH Agent MVP

**Ассоциативно-иерархическое (AH) ядро памяти для текстового LLM-агента.**

`ah-agent-mvp` — когнитивная память: канонический гиперграф знаний, детерминированный
символьный вывод и движок распространения активации. Локальная LLM подсказывает семантику
текста; все канонические решения (кто есть кто, какие домены, какие сущности) принимает
детерминированный код, а не модель.

---

## Что это за проект

Ядро представляет память как **типизированный гиперграф** из семи классов узлов:

| Узел | Роль |
|------|------|
| `S`  | устойчивая лексическая единица / парадигма (слово, предикат) |
| `m`  | сущность-манифестация (конкретный объект/персона) |
| `g`  | логический оператор (AND/OR/NOT/EXISTS/кванторы) |
| `k`  | множество / неопределённая ссылка (`AMBIGUOUS`) |
| `T`  | типизированное утверждение-шаблон (предикат + валентность) |
| `N`  | пропозиция — конкретный факт с актантами |
| `L`  | ассоциативная связь между узлами (`IS-A`, `FOLLOW`, `CAUSE`, …) |

Каждый узел живёт в одном из трёх **доменов**:

- **C** — *canonical* (стабильные факты/знания);
- **P** — *propositional* (текущие рассуждения, выводы);
- **H** — *experiential* (пережитый опыт: диалог, события, следы внимания).

Поверх канонического хранилища лежат производные индексы (полностью перестраиваемые из `AH`),
движок активации и проекция в контекст агента.

## Как работает восприятие текста

Входной текст превращается в типизированные кандидаты, которые после проверки записываются в граф.
Две реализации этого этапа:

- **встроенный адаптивный парсер** — используется по умолчанию;
- **детерминированный формализатор** — включается переменной окружения `AH_FORMALIZER=1`
  (см. «Как пользоваться»). Когда он включён, текст обрабатывает именно он, а не встроенный парсер.

Формализатор проходит последовательные стадии:

1. **Морфологический и лексический анализ.** Для каждого слова определяются лемма, часть речи
   и грамматические признаки (падеж, число, род). Незнакомые слова помечаются отдельно; они не
   «исправляются» по сходству с известными.
2. **Структурные кандидаты.** Из слов собираются возможные предикативные конструкции и их
   участники по заранее объявленным структурным правилам.
3. **Ограниченный выбор LLM.** Модель выбирает значение только из заранее объявленного набора
   вариантов либо сообщает, что данных недостаточно. Она не выдумывает значения и сама не строит
   структуру.
4. **Проверка и решение.** Кандидаты проверяются на согласованность между собой. Если однозначного
   обоснования нет, результат помечается как неоднозначный или неполный — а не угадывается.
5. **Запись в память.** Принятые кандидаты атомарно записываются в граф с опорой на исходное
   наблюдение. При поступлении новых данных решение может быть пересмотрено.

Ключевое свойство: канонические решения (сущности, домены, UID) принимает код, а не модель. У
восприятия ровно два исхода — валидный результат или явная ошибка; ошибка модели не может записать
некорректные данные в память.

## Что умеет

- **Понятная семантика.** Факты хранятся как пропозиции с актантами и логической структурой, поэтому
  над ними работают транзитивность `IS-A`/`FOLLOW`, модус причинности, кванторы (`EXISTS`/универсальные
  правила), временные интервалы и явное опровержение (`FALSE(N)`).
- **Символьный вывод.** Над графом работают логические правила (транзитивность, MP-подобный вывод по
  `CAUSE`, кванторы, временные модусы) — это read-only поиск поверх канонического хранилища.
- **Атомарная управляемая память.** Copy-on-write транзакции, lifecycle (`NEW → REINFORCED → CONSOLIDATED`),
  GC, который не удаляет консолидированные и исторически значимые факты, явная семантическая коррекция
  через `FALSE(N)`.
- **Ассоциативная динамика.** Движок Ignition считает возбуждение `x`, импульсы и веса связей; Workspace
  определяется порогом `x > t`.
- **Локальный self-hosted контур.** Работает с локальными бэкендами (Ollama, LM Studio, HuggingFace в
  отдельном процессе) и имеет мост на Android NPU. Ядро не зависит от `torch`/`transformers`/облака.
- **Прозрачность.** Весь граф виден в GPU-GUI как 2.5D/3D-сцена; есть read-only диагностика, DSL для
  запросов и полный provenance/trace каждого вывода.

## Как пользоваться

### Установка

Требуется **Python ≥ 3.12**. Базовое ядро тянет только `pymorphy3`; остальное — опциональные extras:

```bash
# ядро + тесты
pip install -e ".[test]"

# GUI (PySide6 + VisPy) и локальная LLM (torch/transformers)
pip install -e ".[gui,llm]"

# отдельные бэкенды / возможности
pip install -e ".[llm-lora]"     # LoRA-адаптеры
pip install -e ".[llm-vision]"   # мультимодальность
```

Точка входа — два console-скрипта: `ah-agent` (CLI) и `ah-gui` (GUI).

### GUI (основной способ работы)

```bash
# Windows
run_gui.bat                 # config/default.toml
run_gui_ollama.bat         # бэкенд Ollama
run_gui_lmstudio.bat       # бэкенд LM Studio

# Linux/macOS
./run_gui.sh
# или напрямую:
ah-gui --config config/default.toml
```

GUI строит AH как GPU-сцену (цвет = домен, «жар»/размер узла = возбуждение `x`, белая вспышка =
активация, голубая обводка = Workspace), содержит диалог, полный TOML-редактор конфига с picker'ом пути
к модели и инспектор узлов. Все параметры можно менять из GUI; поля помечены
`LIVE / NEXT_TURN / RESTART_LLM / RESTART_RUNTIME`.

Путь к локальной модели задаётся **только** в конфиге:

```toml
[paths]
llm_model_dir = "C:/Models/Qwen"
```

### Включение детерминированного формализатора

По умолчанию восприятие обрабатывает встроенный адаптивный парсер. Чтобы включить детерминированный
формализатор, задайте переменную окружения перед запуском:

```bash
AH_FORMALIZER=1 ah-gui --config config/default.toml
# или для CLI:
AH_FORMALIZER=1 ah-agent --config config/default.toml <команда>
```

Без этой переменной формализатор не подключается, и используется встроенный парсер.

### CLI (диагностика и загрузка данных)

```bash
ah-agent --config config/default.toml <команда>
```

| Команда | Назначение |
|---------|-----------|
| `summary` | сводка по runtime |
| `dsl "<выражение>"` | выполнить одну DSL-команду/пайплайн |
| `dump-json` / `dump-dot` | дамп канонического/runtime-графа (JSON / Graphviz) |
| `tick [n]` | вручную продвинуть Ignition на n тиков |
| `refute <uid> [--tick]` | создать/повторить `FALSE(N)` и запланировать опровержение |
| `import-corpus <path>` | холодная загрузка структурированного JSON/.ahm/.prj в AH |
| `import-text <path>` | загрузить сырой текст как опыт USER (по умолчанию строгий семантический парсинг) |
| `import-dialogue <path>` | загрузить диалог `ah_dialogue_v1` |
| `import-memory <path>` | заменить живой AH снапшотом персистентности |
| `reset-memory` | очистить AH/runtime/context и заново создать SELF/USER |

Пример DSL:

```bash
ah-agent dsl "findRoles role=LOCATION value=@M_1 domain=H | findLists domain=H | where meta.TYPE=Episode"
```

### Конфигурация

Главный файл — `config/default.toml`; рядом лежат готовые пресеты под бэкенды:
`ollama.toml`, `lmstudio.toml`, `android.toml`. Конфиг управляет: путями и параметрами LLM, начальными
весами интеграции, функциями активации `f/g/h/t/ν`, силой семантических/сенсорных seed'ов, lifecycle/GC,
глубиной и бюджетом вывода, порогом Workspace, бюджетом AgentContext, политикой персистентности, identity
агента/пользователя и числом тиков оркестратора.

## Архитектура (обзор)

Полный когнитивный turn-цикл:

```text
внешний текст
→ восприятие (встроенный адаптивный парсер ИЛИ детерминированный формализатор, AH_FORMALIZER=1)
   → морфология/лексика → структурные кандидаты → ограниченный выбор LLM → проверка и решение
→ атомарный commit в AH + локальный dedup
→ Ignition ticks (распространение активации)
→ Workspace = узлы с x > t
→ Symbolic Inference (транзитивность, кванторы, вывод)
→ опциональная материализация вывода (C < P < H)
→ проекция ACTIVE/DEPENDENCY → AgentContext
→ ответ LLM-агента
→ интеграция ответа (H-only путь) + FOLLOW/episodic history
→ персистентность
```

Подсистемы (подробности — в `docs/IMPLEMENTATION_MAP.md` и `docs/reference/Архитектура_v3.md`):

1. **AH Core** — каноническое хранилище, типизированные ссылки, глобальные UID, атомарные транзакции,
   производные индексы.
2. **Восприятие текста** — встроенный адаптивный парсер (по умолчанию) или детерминированный формализатор
   (`AH_FORMALIZER=1`); два исхода: валидный результат / явная ошибка.
3. **Deterministic Integration** — валидация, разрешение сущностей/кореференции/деиксиса, маршрутизация
   C/P/H, атомарный commit.
4. **Ignition Engine** — синхронные тики, `f(x,z)`, затухание, pacemaker `ν`.
5. **Lifecycle + GC** — `NEW→REINFORCED→CONSOLIDATED`, безопасное удаление orphan'ов.
6. **Workspace → AgentContext** — проекция ACTIVE/DEPENDENCY.
7. **Symbolic Inference** — role-fill, транзитивность, MP-подобный вывод, кванторы; read-only search.
8. **DSL / canonical API** — высокоуровневые запросы поверх канонической границы записи.
9. **Explicit FALSE / коррекция** — опровержение как `FALSE(N_old)`, вес корректируется через `h_N`.
10. **ν pacemaker + часы** — внутренние импульсы и опциональный wall-clock драйв.
11. **Diagnostics** — read-only инспектор, трассировка, CLI-дамп.
12. **Persistence** — атомарный JSON (temp → `os.replace`), перестройка индексов после load.
13. **Full Turn Orchestrator** — связывает всё выше в один цикл (`AgentOrchestrator`).
14. **Local LLM process boundary** — локальная модель в отдельном процессе (JSONL); ядро не зависит от
    torch/CUDA.
15. **GPU GUI** — PySide6 + VisPy, 2.5D/3D-сцена графа, редактор конфига, инспектор узлов.

## Структура проекта

```text
config/            # default.toml + пресеты (ollama/lmstudio/android)
prompts/          # agent.txt, system.txt, perception/*.txt (короткие пробы)
schemas/          # JSON-схемы протоколов
docs/             # архитектура, implementation map, reference/, archive/slices/
src/ah/           # ядро: model, core, perception, integration, ignition,
                  #   inference, projection, llm, agent, gui, dsl, corpus, ...
src/ah/formalizer/# детерминированный формализатор (включается AH_FORMALIZER=1)
tests/            # unittest-свит + acceptance-фикстуры
android/          # Android NPU bridge (Kotlin)
```
