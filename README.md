# AG Memory

**Долговременная память для языковых агентов.**

AG Memory связывает сообщения с их смыслом, участниками и уже известными сведениями. Память сохраняет историю взаимодействия, поддерживает ассоциативное вспоминание и предоставляет агенту актуальный контекст.

Ниже — один пример. Он показывает основные принципы архитектуры без внутренних форматов и подробностей реализации.

---

## Одна реплика

> Привет, Я - твой ИИ ассистент Крипл!

Допустим, эту фразу произнесла сама Крипл в диалоге с пользователем. Автор и адресат сообщения известны из контекста беседы.

Внутри одной реплики содержится несколько разных смысловых частей.

### 1. Сохраняется событие общения

Память фиксирует исходную фразу, её автора и адресата. Приветствие становится частью истории диалога.

При последующем обращении можно установить не только содержание сообщения, но и **кто, кому и в каком контексте его произнёс**.

### 2. Выделяются смысловые связи

В выражении «Привет» распознаётся **приветствие**. «Я» указывает на **говорящего**. «Твой» относится к **адресату**. «ИИ ассистент» задаёт **названную роль**, а «Крипл» — **названное имя**.

![Смысловые части реплики Крипл](docs/assets/cripl-utterance.svg)

Связь слова «я» с Крипл устанавливается благодаря известному автору сообщения. Одна лишь фраза без сведений об отправителе не позволяет достоверно определить, кто именно представляется.

### 3. Сведения находят место в памяти

У памяти уже могут быть представления о Крипл, пользователе и роли ассистента. Новая реплика добавляет к ним связи и сохраняет источник этих сведений.

В упрощённом виде содержание можно прочитать так:

**Крипл** — говорящий; **ИИ-ассистент** — роль, которую она себе приписывает; **пользователь** — адресат; **«Привет»** — действие в диалоге.

Самопредставление сохраняется как высказывание конкретного автора. Подтверждение имени, роли и других фактов определяется доступными основаниями. Сведения не становятся безусловно истинными только потому, что появились в тексте.

### 4. Связи участвуют во вспоминании

Позже пользователь спрашивает: **«Как тебя зовут?»**

Запрос активирует связанные сведения о говорящем, имени и предыдущем общении. Актуальная часть памяти образует **рабочее пространство**, из которого агент получает нужный контекст.

![Упрощённый фрагмент памяти Крипл и активация связанных узлов](docs/assets/cripl-associations.svg)

На схеме зелёным отмечены более активные элементы. Активация помогает найти релевантное содержание; правильность ответа зависит от сохранённых оснований и установленной связи с говорящим.

Если имя Крипл подтверждено в текущем контексте, агент может ответить: **«Меня зовут Крипл».**

### 5. Память сохраняет изменения

Если позднее информация об имени или роли уточняется, появляется новое основание для её интерпретации. История исходной реплики остаётся доступной. Актуальное содержание определяется действующими связями и основаниями.

## Что объединяет AG Memory

**Семантическая структура.** Память представляет сущности, свойства, отношения и события вместе с их связями.

**Ассоциативная активация.** Контекст и новые сообщения активируют связанные части памяти. Так формируется рабочее пространство текущего взаимодействия.

**Логические отношения.** Когда высказывание содержит отрицание, условие или квантор, эти особенности учитываются в смысловом представлении и при допустимом выводе.

**Основания и история.** Для сохранённых утверждений учитываются источники, интерпретации и изменения. Это позволяет пересматривать сведения, сохраняя историю.

**Связь с языковым агентом.** Формализатор отвечает за интерпретацию входных сообщений; агентская языковая модель использует подготовленный контекст для ответа. Это разные роли, даже если обе выполняет одна и та же модель.

## Установка и встраивание

Для локальной работы требуются **Python 3.12+**, **uv** и подключённая языковая модель, например через Ollama или LM Studio.

```bash
git clone --branch temp https://github.com/MaxSquizie/AG_Memory.git
cd AG_Memory
uv venv
uv pip install -e ".[gui]"
```

После настройки модели и ресурсов запустите графический интерфейс:

```bash
uv run ah-gui --config config/ollama.toml
```

Формализатор V7 требует подготовленного и проверенного набора ресурсов. Настройка модели, проверка ресурсов и запуск подробно описаны в [инструкции по эксплуатации](docs/RUN.md).

Для встраивания памяти в собственное приложение используются компоненты ядра и интерфейс агента из каталога `src/ah/`. Их расположение приведено в [карте реализации](docs/IMPLEMENTATION_MAP_V7.md).
